## 0. 一页结论

**v3 解决「链路可回放」，v4 解决「边界可核验」。**

| 维度 | v3 | v4 |
| --- | --- | --- |
| 库内未命中 | 直接答「库内暂无」，不补常识 | 允许模型通识回答，但强制分区标注 |
| 疾病名提问 | 按征象名检索，必然未命中 | 新增概念索引，疾病 → 征象可落地 |
| 证据强度 | 只有「命中/未命中」 | `grounded` / `mixed` / `general` 三态 |
| 引用审计 | 只查 id 是否在库内 | 追加「通识段不得出现 id」 |
| 前端回执 | 显示阶段与耗时 | 追加三色证据标签与库外提示 |

一句话：**从「不敢答」变成「分层答」，而且每句话都能看出是哪一层。**

## 1. v3 遗留的三个问题

### P0-1 库内未命中即拒答

`yingzhi.md` 规则 8「不补常识」、规则 9「未命中就直接回答」，配合技能的「三步无命中答库内暂无」，
把模型锁成纯检索器。截图中的「肺水肿的征象 → 库内暂无」就是这条链路的必然结果。

### P0-2 疾病名与征象名混为一谈

`signs.jsonl` 只收征象（磨玻璃影、实变），不收疾病（肺水肿、肺隔离症）。
按疾病名去 `signs.jsonl` 找同名条目，永远找不到；但相关征象其实写在 `may_see_in` 里。
这是索引维度问题，不是知识缺失问题。

### P0-3 一旦放开通识，就有冒充证据的风险

模型很容易在「通识补充」里顺手写一个 `SIGN-018`。该 id 在库内真实存在，
但那段话并不是从该词条读出来的。若审计只检查「id 是否存在」，这种混用会被放过。

## 2. v4 设计：三层

### 第 1 层 · 疾病/病理概念索引

新增 `kb/data/concepts.jsonl`，由 `yingzhi/scripts/build_concepts.py` 从 `signs.jsonl` 的
`may_see_in` 反向聚合生成，人工种子补英文名、别名、关联征象。

字段契约：

| 字段 | 含义 | 回答时的口径 |
| --- | --- | --- |
| `id` | `CON-xxx` | 可引用，但不替代 SIGN id |
| `name` / `en` / `aliases` | 概念名与检索别名 | 用于问题归一化 |
| `sign_ids` | `may_see_in` 原文直接支持 | 库内证据，逐条带 id |
| `related_sign_ids` | 人工补充的病理关联 | 必须标「关联」，不得当作原文 |
| `guideline_ids` | 相关指南条款 | 有则引用，无则为空 |
| `note` | 一句话提示 | 只作补充，不单独充当结论 |

当前规模：60 条征象 → 136 个概念。示例：

```json
{"id":"CON-012","name":"肺水肿","sign_ids":["SIGN-001","SIGN-002","SIGN-014"],
 "related_sign_ids":["SIGN-007","SIGN-010"]}
```

### 第 2 层 · 检索四步与回答三态

检索顺序：`词条精确名 → 词条别名/英文 → 概念 → 概念下 sign_ids 回查`，最多 4 条命令，命中即停。

| 状态 | 触发 | 硬要求 |
| --- | --- | --- |
| `grounded` | 库内命中且证据完整 | 事实断言必须带 id |
| `mixed` | 概念命中 + 通识补充 | 库内段带 id；通识段以 `【通识补充·非库内证据】` 开头 |
| `general` | 库内完全未覆盖 | 通识段禁止出现任何 id；`cited` 为空 |

合规边界不变：不回答诊断、治疗、用药、手术、预后。

### 第 3 层 · 审计与展示

服务端 `yingzhi/serve/main.py`：

- `suggest_concept(query)`：疾病名 → 概念条目，返回 `sign_ids` / `related_sign_ids`；
- `general_section_ids(text)`：抓通识段越界 id，**即使 id 真实存在也报**；
- `detect_grounding(text, kb_hits)`：返回 `grounding` 与 `marker_ok`；
- `done` 事件新增 `grounding`、`marker_ok`、`general_section_ids`；
- `trace.json` 的 `citation_audit` 同步落盘，`ok` 同时要求无编造 id、无通识段越界 id。

前端：

| 标签 | 含义 |
| --- | --- |
| 绿 · 库内证据 | `grounded` |
| 黄 · 库内证据 + 通识补充 | `mixed` |
| 红 · 纯通识 / 越界 id / 未标注通识来源 | `general` 或审计不通过 |

`general` 时额外显示「库外问题」横幅，明确「不是本库证据，不能当作可核验引用」。

## 3. 接口变更

`POST /api/ask` 的 SSE `done` 事件：

```json
{
  "grounding": "grounded|mixed|general|degraded",
  "marker_ok": true,
  "general_section_ids": [],
  "unverified_citations": [],
  "cited": ["SIGN-001", "SIGN-002", "SIGN-014"]
}
```

`trace.json`：

```json
{
  "summary": {"grounding": "grounded"},
  "citation_audit": {
    "cited": [], "unverified": [], "general_section_ids": [],
    "grounding": "grounded", "marker_ok": true, "ok": true
  }
}
```

旧前端不读新字段也不会报错；新前端缺字段时按「证据来源未知」处理，不默认放行。

- 规则 8 改为「疾病名不等于征象名，先查 concepts 再回查 signs」；

- 规则 10 改为「最多 4 条命令，命中即停」；
- 新增规则 11「`related_sign_ids` 必须标关联」。

`retrieve-sign/SKILL.md`：

- 检索路径表新增 `concepts.jsonl`；
- 三步法扩为四步法；
- 新增「通识分支」五条硬约束；
- 输出格式从两态扩为 A/B/C 三态模板。

## 6. 运行与回滚

```bash
python3 yingzhi/scripts/build_concepts.py          # 概念索引
python3 yingzhi/serve/main.py --port 8800          # 动态层
cd outputs/medtrain && python3 -m http.server 8080 --bind 127.0.0.1
```

回滚到 v3：不恢复 `versions/v4` 即可；v3 的提示词与检索逻辑仍保留在
`docs/软件搭建方案_v3.md` 与对应历史文档中。需要代码级回滚时按
[versions/v4/MANIFEST.md](../versions/v4/MANIFEST.md) 第 3 节反向操作。
