# 全站收缩记录（v7）

日期：2026-11-20
范围：`outputs/medtrain` 对外站点

## 1. 收缩前

站点同时存在两套外壳：

- `read/` 四页：胸片阅片、分区图谱、组卷自测、报告对照；
- `app.html` 三角色 SPA：问、学、迁、练、用五条链路，外加人体 3D 模型；
- 首页有全库入口、四链条、三端角色、PWA 四快捷方式；
- `dev/` 还有 8 个固定角色/设备入口。

结果是入口多、主链路不突出，评委无法在 3 分钟内看清“到底做什么”。

## 2. 收缩后

对外只剩两个页面：

| 路径 | 职责 |
| --- | --- |
| `index.html` | 一句话定位、四种状态示例、范围与边界 |
| `read/clinic.html` | 唯一功能页：21 例 CR 胸部逐区阅片 |

旧入口全部改为跳转：

- `app.html` → `read/clinic.html`
- `read/index.html`、`read/teach.html`、`read/paper.html`、`read/compare.html` → `read/clinic.html`
- `dev/*.html` → `../read/clinic.html`

## 3. 构建收缩

`medtrain/build.py` 不再：

- 复制 `core.js` / `learn.js` / `ask.js` 等 SPA 脚本；
- 复制 `models/`、`vendor/`、`data/kb.js`；
- 生成 `dev/` 角色/设备入口；
- 依赖 `build_data.py`。

现在只：

1. 运行 `build_chest_reading.py` 生成逐区数据；
2. 运行 `build_teach_pages.py` 复制 5 个 clinic 资源与 23 张胸片；
3. 写首页、跳转页、README。

`manifest.webmanifest` 只保留「胸片阅片」一个快捷方式，`start_url` 指向 `read/clinic.html`。

## 4. 保留的判断

- 四种状态 `abnormal / normal / unmentioned / limited`；
- 21 例队列，CASE-019、CASE-201 移出；
- 逐区文本、依据、SHA-256、出处；
- 阅片记录导出；
- 纯静态、不调大模型、未入库影像拒绝；
- 非诊断声明与医学审核提示。

## 5. 验收

```bash
python3 medtrain/build.py
python3 kb/scripts/selfcheck_chest_reading.py   # 183/183
python3 medtrain/tests/chest_check.py           # 35/35
python3 medtrain/tests/site_check.py            # 18/18
```

`site_check.py` 覆盖：

- 首页只保留 `read/clinic.html` 与 `#method` 两类内链；
- 首页与 clinic 无 console / page error、无 4xx；
- clinic 导航只保留「胸片阅片」「方法与边界」两项，队列 21 例；
- `app.html`、`read/index.html`、`read/teach|paper|compare.html`、`dev/student.html` 全部跳转到 clinic；
- manifest 只有 1 个快捷方式，`start_url` 指向 clinic；
- `read/` 下没有旧页脚本残留。

构建目录从约 40 MB 收缩到 7.5 MB，只保留首页、clinic、23 张胸片、数据和报告。

## 6. 风险与后续

- 旧构建目录里仍保留未引用的 SPA 脚本、模型和全库数据；它们不再被任何对外页面加载。
  如需进一步减小部署体积，可在确认后清理 `outputs/medtrain` 的未引用资源并重新构建。
- 非胸片数据仍在 `kb/data`，只是不再进入对外站点；后续如恢复，需要重新逐区校正。
- 逐区文本仍须医学人员审核签字。
