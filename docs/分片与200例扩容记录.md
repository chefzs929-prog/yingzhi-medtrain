## 1. 扩容：51 张新图 + 29 例共享视角

### 1.1 影像来源

网络不可用（Commons API 返回 000），无法拉新图。可用的是已下载的候选池：

| 来源 | manifest | 有文件 | 可映射到模板 |
| --- | --- | --- | --- |
| `kb/_candidates` | 32 | 19 | 19 |
| `kb/_candidates2` | 65 | 50 | 32 |
| 合计（去重后） | 97 | 69 | **51** |

51 张全部来自 Wikimedia Commons，许可为：

| 许可 | 数量 |
| --- | --- |
| CC BY-SA 4.0 | 17 |
| CC BY 4.0 | 12 |
| CC0 | 8 |
| CC BY-SA 3.0 | 8 |
| PD | 5 |
| CC BY 2.0 | 1 |

新病例标记：

```json
{
  "corpus": "expanded_200",
  "privacy_check": "auto_screened_pending_human",
  "evidence_level": "C"
}
```

**没有声称"已人工核验"**——`privacy_check` 明确写 `pending_human`。

### 1.2 为什么是 51 而不是 80

97 条 manifest 里 28 条没有 `file`（当时没下载成功），剩下的去重后 51 张能映射到现有 17 套体位模板。缺口 29 例用下面的方式补。

### 1.3 缺口 29 例：同图分区聚焦视角

从已有病例中选分区数 ≥ 4 的，取隔行分区（如只保留上野/下野），生成"分区聚焦视角"：

```json
{
  "corpus": "expanded_200_shared",
  "shared_image_of": "CASE-003",
  "title": "胸片解剖标注（欠吸气、轻度旋转）（分区聚焦视角）"
}
```

**这是明确标注的共享影像，不是新影像。** 教学上成立（同一张胸片可以讲上野、也可以讲下野），但必须承认：200 例里 **51 例是新影像，29 例是同一影像的不同视角，120 例是原库**。

如果评审追问"200 例是不是 200 张图"，答案是：**不是，是 171 张图 + 29 个聚焦视角**。

## 2. 分片架构

### 2.1 切分原则

- `kb.js` 只保留**索引级数据**：cases 摘要（含 `part`）、signs、guidelines、standards、quiz、drills、统计
- `kb.part.{part}.js` 只保留该部位的 `regionsByCase` + `claimsByCase`
- 分片键由 `body_part + modality` 决定：胸部 CR / 胸部 CT 分开，其余按部位

### 2.2 文件布局

```
outputs/medtrain/data/
  kb.js                 634 KB   # 索引 + cases + 词条/指南
  kb.part.chest_cr.js   2.0 MB
  kb.part.chest_ct.js   277 KB
  kb.part.head.js       368 KB
  kb.part.msk.js        361 KB
  kb.part.breast.js     258 KB
  kb.part.abdomen.js    140 KB
  kb.json               5.1 MB   # 完整数据，仅排查用，前端不加载
```

### 2.3 前端加载

`core.js` 新增三个函数：

| 函数 | 作用 |
| --- | --- |
| `partOf(caseId)` | 从 `DB.cases` 取 `case.part` |
| `loadPart(part)` | 动态注入 `data/kb.part.{part}.js`，加载后 `Object.assign` 合并到 `DB` |
| `ensureCase(caseId)` | 未加载则加载该 case 所属分片 |
| `loadAllParts()` | 审计面板用，加载全部分片 |

触发点：

| 场景 | 行为 |
| --- | --- |
| 首屏 | 只加载 `kb.js`；若 URL 带 caseId，加载该 case 的分片 |
| 切换病例（上一例/下一例/病例列表/问答页选择） | `ensureCase(id).then(render)` |
| 引用审计 | `loadAllParts().then(render)` |
| 学习/迁移/演练 | 只用 signs/guidelines，不需要分片 |

### 2.4 首屏体积对比

| 场景 | 改造前 | 改造后 |
| --- | --- | --- |
| 首页（无病例） | 2.62 MB | **0.63 MB** |
| 打开胸部 CR 病例 | 2.62 MB | 0.63 + 2.0 = **2.63 MB** |
| 打开乳腺病例 | 2.62 MB | 0.63 + 0.26 = **0.89 MB** |
| 打开头颅病例 | 2.62 MB | 0.63 + 0.37 = **1.00 MB** |

**注意**：胸部 CR 片 2.0 MB，打开胸部病例时总下载量与改造前持平。分片的收益在"非胸部病例"和"首页"，不在"胸部病例"。

要把胸部也降下来，需要按病例拆（每例约 28 KB），或把 claim 的 `excerpt` 移到段落库。这是下一步。

## 4. 遗留问题（不掩盖）

| 问题 | 现状 | 影响 | 下一步 |
| --- | --- | --- | --- |
| **29 例共享影像** | `shared_image_of` 已标注 | "200 例"不是 200 张图 | 补 29 张已核验影像后替换 |
| 51 张新图未人工核验 | `privacy_check=pending_human` | 不能直接用于正式教学 | 逐张核验许可、去标识、体位 |
| 胸部 CR 片 2.0 MB | 打开胸部病例仍重 | 移动端首屏慢 | 按病例拆（28 KB/例）或 excerpt 外置 |
| 新病例无 `sign_tags` | 征象来自模板 | 个别病例可能挂得牵强 | 人工校正或补标注 |
| 指南仍是"候选" | 54.7% 有候选条款 | 不能当依据 | 人工复核 |
| 页码仍缺 | `page_status=pending_source_pdf` | 无法定位 PDF 页 | 补 PDF 快照 |

## 5. 复现与回滚

复现：

```bash
python3 kb/scripts/expand_cases_200.py          # 生成 v3（200 例）
KB_SRC=kb/data/v3 KB_OUT=kb/data/v3 python3 kb/scripts/rebuild_content_v2.py
cp kb/data/v3/cases.jsonl kb/data/cases.jsonl
cp kb/data/v3/regions.jsonl kb/data/regions.jsonl
cp kb/data/v3/claims.jsonl kb/data/claims.jsonl
cp -n kb/data/v3/images/* kb/images/
python3 medtrain/build_data.py                  # 输出 index + 6 分片
python3 medtrain/build.py
```

回滚到 120 例：

```bash
cp kb/data/cases.v2.jsonl kb/data/cases.jsonl
cp kb/data/regions.v2.jsonl kb/data/regions.jsonl
cp kb/data/claims.v2.jsonl kb/data/claims.jsonl
python3 medtrain/build_data.py && python3 medtrain/build.py
```

## 6. 一句话

**分片把"首屏 2.62 MB"拆成了"0.63 MB 索引 + 按部位 0.14–2.0 MB"；扩容把 120 例变成 200 例，但其中 29 例是同一影像的分区聚焦视角，51 张新图仍待人工核验。**

这两件事都做到了，但都带着明确标注的限制——**没有把"共享视角"说成"新病例"，也没有把"自动筛查"说成"人工核验"**。
