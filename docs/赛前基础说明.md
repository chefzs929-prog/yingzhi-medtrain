# 赛前基础说明：这个项目从零开始搭建

> 一句话：RadioCheck 是在 2026-11 黑客松期间，从空目录开始搭出来的胸片阅片教学网站。不是拿现成项目改的，也没有可复用的前端脚手架或现成知识库。

## 1. 起点是什么

第一次提交（2026-11-18）之前，工作区里没有：

- 前端页面、组件库或设计系统；
- 后端服务、数据库或检索索引；
- 影像数据集、分区标注、征象词条、指南条款；
- 测试、构建脚本或部署流程。

第一版提交的内容就是「200 例知识库 + 分片加载 + 双引用问答」的最小闭环，此后所有页面、接口、数据和测试都是在这条主线上迭代出来的。

## 3. 从零跑通（最短路径）

```bash
# 1) 只装运行验收需要的依赖（语义检索与工作流是纯标准库，不需要额外包）
python3 -m pip install -r requirements.txt

# 2) 一条命令跑完：知识库单测 + 语义/工作流单测 + 拒答集 + 全站验收
bash scripts/verify_all.sh

# 3) 起动态服务看完整演示（上传影像、双引用、健康检查）
python3 yingzhi/serve/main.py --port 8800 --site outputs/medtrain
# 浏览器打开 http://127.0.0.1:8800/read/clinic.html
```

静态预览（不含 `/api`）也能看页面，但上传影像的视觉定位、语义检索与健康检查需要动态服务。

## 4. 技术选型与取舍

- **纯 Python 标准库优先**：语义检索（TF-IDF 字符 1–2 gram + 余弦）和五步工作流都不依赖 numpy/torch，降低现场复现门槛；numpy 只用于可选的向量化路径。
- **静态站点 + 同源 `/api`**：页面可以直接静态托管，也可以由 `main.py` 同源托管；不需要前端构建框架，构建脚本只做数据与页面复制。
- **双引用优先于覆盖率**：影像侧（分区 + bbox + 来源）和文献侧（条款/词条原文 + 出处）缺一，就拒答，不拼半条引用。
- **只做胸片专项**：分区模板、逐区标注、征象词条和指南条款都要人工校对；先把胸片这一条线做到每个分区都有出处，再谈其他部位。

## 5. 目录地图

| 路径 | 作用 |
| --- | --- |
| `kb/data/` | 影像元数据、分区、征象、概念、指南条款、段落 |
| `kb/app/` | 阅读页源码（clinic / exam / compare / classroom / methods 等） |
| `kb/scripts/` | 数据构建、自检、评测脚本 |
| `yingzhi/serve/` | 本地动态服务：知识库 API、语义检索、五步工作流、视觉区域定位 |
| `medtrain/build.py` | 构建 `outputs/medtrain` 静态站点 |
| `medtrain/tests/` | 全站验收（`site_check.py`）与拒答集（`refusal_eval.py`） |
| `scripts/verify_all.sh` | 一条命令跑完全部验收 |
| `docs/` | 设计、边界、反馈与未来拓展说明 |

## 6. 当前边界（如实写）

- 只支持 CR 胸片（正位 / 侧位）；胸部 CT、乳腺 MG、腰椎 MRI、超声等其他影像明确不支持，后端返回 `unsupported_modality`，见 [反思与未来拓展方向](反思与未来拓展方向.md)。
- 语义检索是稀疏向量 + 余弦，不是神经网络 embedding。
- 工作流是本地五步编排（parse → retrieve → locate → compose → audit），不是 DeepWorks 界面的可视化工作流；后者仍需人工在平台创建。
- 无视觉模型时，上传影像按胸片默认模板定位，并明确提示「如果这不是胸片，请勿使用该分区」。
