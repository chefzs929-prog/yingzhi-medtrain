# 影知工作流 · 搭建手册（逐步操作版）

> 目标：在 DeepWorks 里建一条 3 步工作流，让「胸片问题」进去、「带双引用的回答」出来。
> 全程约 5 分钟。照着填，不要跳步。

---

## 第 0 步：三条前置检查（必须全过）

在项目根目录 `/Users/fz/Desktop/黑客松` 下执行：

```bash
# 1 技能文件在不在
ls .opencode/skills/radhearing-ask/SKILL.md

# 2 脚本能不能答
python3 .opencode/skills/radhearing-ask/scripts/ask.py "右肺中野有什么问题" --case CASE-006

# 3 脚本能不能拒答
python3 .opencode/skills/radhearing-ask/scripts/ask.py "这张片子是不是肺癌" --case CASE-006
```

第 2 条必须出现这 5 个锚点，缺任何一个都不要往下走：

```
右肺中野（RML）
left=0.06
GL-PNE-02
第 68 字起
f25ddcf0
```

第 3 条必须出现：

```
不能回答　·　超出诊断范围
```

**这一步不过，工作流一定不过。** 先修脚本。

## 第 1 步：找到工作流入口

DeepWorks 不同版本入口位置略有差异，按顺序找：

1. 左侧边栏 →「工作流」/「Workflow」/「编排」
2. 左侧边栏 →「能力」/「扩展」→ 工作流
3. 设置 → 工作流 / 自动化
4. 顶部「+ 新建」→ 工作流

找到后点「新建工作流」。**注意：必须在打开本项目（`黑客松`）的会话里建**，否则技能列表里看不到 `radhearing-ask`。

---

## 第 2 步：填基本信息

| 字段 | 填这个 |
| --- | --- |
| 名称 | `影知 · 影像双引用问答` |
| 描述 | `输入胸片问题，输出带区域锚点与文献锚点的回答；无证据或超出范围时拒答` |
| 触发方式 | 手动触发 / 对话输入 |

保存后进入画布。

---

## 第 3 步：节点 1（输入）

在画布上点「+」→ 选「输入」/「开始」/「Input」。

| 字段 | 填这个 |
| --- | --- |
| 节点名 | `问题输入` |
| 变量名 | `question` |
| 类型 | 文本 / String |
| 必填 | 是 |
| 默认值 | 留空 |
| 示例值 | `右肺中野有什么问题` |

再点一次「+ 添加变量」，加第二个：

| 字段 | 填这个 |
| --- | --- |
| 变量名 | `case_id` |
| 类型 | 文本 |
| 必填 | 否 |
| 默认值 | `CASE-006` |

> 如果界面只允许一个输入变量，就只留 `question`，病例号写死在下一步的命令里。

---

## 第 4 步：节点 2（技能 / Agent）

这是整条工作流的关键节点。先判断你的界面给的是哪种节点。

### 情况 A：能直接选「技能 / Skill」节点（首选）

点「+」→ 选「技能」→ 在技能列表里搜 `radhearing` → 选中 `radhearing-ask`。

| 字段 | 填这个 |
| --- | --- |
| 节点名 | `双引用问答` |
| 技能 | `radhearing-ask` |
| 入参 `question` | 点「插入变量」选 `question`（不要手打） |
| 入参 `case` | 点「插入变量」选 `case_id` |
| 超时 | `60` 秒 |

入参映射如果只能填一段文本，就填：

```
question={{question}} case={{case_id}}
```

**保存后直接跳到第 5 步。**

### 情况 B：只有「Agent / 大模型」节点

这种节点默认**不会执行本地脚本**，它会凭训练记忆编一个"看起来很对"的答案。必须用提示词强制它跑脚本。

先把节点配置成：

| 字段 | 填这个 |
| --- | --- |
| 节点名 | `双引用问答` |
| 模型 | 任意可用模型 |
| 工具 / 能力 | 勾选「终端」「命令执行」「Bash」这类权限（没有就勾不了，见下方警告） |
| 超时 | `60` 秒 |

提示词整段粘贴（把变量占位符换成界面上的插入变量）：

```
你是影知问答的执行器，不是医生。

任务：调用本地脚本回答问题，然后原样返回脚本结果。

第一步，执行这条命令（在项目根目录）：
python3 .opencode/skills/radhearing-ask/scripts/ask.py "{{question}}" --case {{case_id}}

第二步，把脚本 stdout 原样作为最终回答输出。

硬性要求：
1. 禁止自己写医学结论，禁止补充脚本没有的内容。
2. 禁止改写数字、分区名、kp_id、字符 offset、校验码。
3. 脚本输出以「不能回答」开头时，保留拒答理由和「你可以问」的替代问法。
4. 如果命令执行失败，直接输出「脚本执行失败：<错误原文>」，不要用记忆代替。
5. 结尾保留脚本自带的非诊断声明。
```

> **警告**：如果这个 Agent 节点勾不到终端/命令执行权限，它 100% 会编答案。这种情况不要硬用，改用情况 A，或退回第 9 节的 Plan C。

---

## 第 5 步：节点 3（输出）

点「+」→ 选「输出」/「结束」/「Output」。

| 字段 | 填这个 |
| --- | --- |
| 节点名 | `回答输出` |
| 输出变量 | `answer` |
| 取值来源 | 上一步节点的输出 |
| 格式 | Markdown |

如果界面有「输出模板」输入框，粘贴：

```
{{answer}}

---
本回答仅用于教学，不构成诊断意见
```

> 脚本本身已带声明，模板再加一行是双保险；如果发现重复，删掉模板这一行。

---

## 第 6 步：连线并保存

1. 输入节点右侧圆点 → 拖到技能节点左侧圆点
2. 技能节点右侧圆点 → 拖到输出节点左侧圆点
3. 点「保存」/「发布」/「启用」

画布上应该是 **3 个节点、2 条线**，没有孤立节点。

## 第 7 步：跑三条测试（对照下面的真实输出）

### 测试 1：可答

输入 `右肺中野有什么问题`，`case_id` 填 `CASE-006`。

**必须看到**（这是脚本真实输出，可逐字对照）：

```
**可以回答**　·　置信度 高

右肺中野大片实变，红箭头指向病灶边缘。

**影像区域**
- 分区：右肺中野（RML）
- 病例：CASE-006　大叶性肺炎（箭头标注）
- 归一化坐标：left=0.06 top=0.33 w=0.3 h=0.24
- 影像：images/case-006.jpg

**依据原文**

> 实变内出现支气管充气征，提示病变位于肺泡腔，支持肺泡性实变而非支气管阻塞。

— 肺炎 / 肺实变 · `GL-PNE-02` · 第 68 字起 · 校验 `f25ddcf0`
```

**判真标准**：出现 `GL-PNE-02` 且出现 `第 68 字起`。
只有"右肺中野有实变"这类通顺话、没有这两个锚点 → 模型在编，回第 4 步。

### 测试 2：拒答（诊断类）

输入 `这张片子是不是肺癌`。

**必须看到**：

```
**不能回答**　·　超出诊断范围

这个我不能答。

库内是教学分区标注，不包含病理或恶性诊断依据。仅凭胸片分区描述不能判断良恶性，需要病理、增强 CT 或多学科会诊。

**你可以问**：这张片子有没有结节？结节的部位和大小来源是怎么描述的？
```

### 测试 3：拒答（模态类）

输入 `这张 CT 有没有脑出血`。

**必须看到**：

```
**不能回答**　·　超出影像模态

本项目的数据与标注全部是胸部 X 线正侧位片，不包含 CT、MRI、超声或核医学影像。

**你可以问**：这张胸片上纵隔区域来源是怎么描述的？
```

三条都对，工作流才算跑通。少一条都不算。

## 第 9 步：报错对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 技能列表搜不到 `radhearing-ask` | 项目技能没加载 / 不在本项目会话 | 确认 `.opencode/skills/radhearing-ask/SKILL.md` 存在，重开会话，确保工作区是 `黑客松` |
| 节点报 `command not found: python3` | 运行环境 PATH 不同 | 改用 `python`，或写绝对路径 `/usr/bin/python3` |
| 节点报找不到 `ask.py` | 工作目录不是项目根 | 命令前加 `cd /Users/fz/Desktop/黑客松 &&` |
| 输出通顺但无 `GL-PNE-02` | Agent 节点凭记忆作答 | 回第 4 步情况 B，检查终端权限；不行就换技能节点 |
| 输出被截断 | 超时太短 | 超时改 90 秒 |
| 拒答变成"建议就医" | 提示词被模型改写 | 明确要求"保留脚本 refusal 原文" |
| 声明重复两遍 | 脚本自带 + 模板又加 | 删模板里的声明行 |

## 附：结构化输出版（可选，加分项）

脚本支持 `--json`，适合输出节点拆字段。命令改成：

```bash
python3 .opencode/skills/radhearing-ask/scripts/ask.py "{{question}}" --case {{case_id}} --json
```

返回结构：

```json
{
  "status": "answer",
  "region": { "zone_id": "RML", "label": "右肺中野", "coords": [0.06, 0.33, 0.3, 0.24] },
  "citation": { "kp_id": "GL-PNE-02", "offset": 68, "sha1": "f25ddcf08d83e5..." }
}
```

`status` 有三个值：`answer` / `refusal` / `unknown`，可以直接做分支判断。

输出模板可以写成：

```
### 区域
{{region.label}}（{{region.zone_id}}）

### 文献
「{{citation.quote}}」— {{citation.kp_id}} · 第 {{citation.offset}} 字起
```

> 如果输出节点不支持点号取值，就不要用 JSON 版，保持 Markdown 版最稳。
