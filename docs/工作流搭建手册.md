# 影知平台链路 · 搭建手册（技能 + 自动化任务）

> 目标：在 DeepWorks 内让「胸片问题」进去、「带双引用的回答」出来，并把回归检查固化成可定时执行的自动化任务。
>
> **平台事实（2026-11-24 实测）**：DeepWorks 桌面端个人版当前**没有可视化工作流编排画布**，扩展能力只暴露 `deepworks-automation`（自动化任务）。因此本手册按「技能（Skill）+ 自动化任务（Automation）」编写，不再要求创建 3 节点画布。
>
> 如果后续版本开放工作流画布，旧版 3 节点字段映射保留在文末附录，可直接照搬。

## 第 1 步：在会话里跑通技能链路

DeepWorks 的技能入口就是当前项目会话，不需要进任何画布。

### 方式 A：命令（最稳）

在会话输入框输入：

```
/radhearing 右肺中野有什么问题
```

对应 `.opencode/command/radhearing.md`，会把问题转给 `radhearing-ask` 技能。

### 方式 B：自然语言

```
用 radhearing-ask 技能回答：右肺中野有什么问题，病例 CASE-006
```

技能会调用 `.opencode/skills/radhearing-ask/scripts/ask.py`，返回带区域锚点与文献锚点的回答；越界问题返回拒答与替代问法。

> 技能只在**本项目会话**里可见；换工作区后技能列表会变。

## 第 2 步：跑三条验收（对照真实输出）

### 测试 1：可答

输入 `右肺中野有什么问题`，病例 `CASE-006`。

**必须看到**（脚本真实输出，可逐字对照）：

```
**可以回答**　·　置信度 高

右肺中野大片实变，红箭头指向病灶边缘。

**影像区域**
- 分区：右肺中野（RML）
- 病例：CASE-006　大叶性肺炎（箭头标注）
- 归一化坐标：left=0.06 top=0.33 w=0.3 h=0.24
- 影像：images/case-006.jpg

**依据原文**

> 实变内出现支气管充气征，提示病变位于肺泡腔，支持肺泡性实变而非支气管阻塞。

— 肺炎 / 肺实变 · `GL-PNE-02` · 第 68 字起 · 校验 `f25ddcf0`
```

**判真标准**：出现 `GL-PNE-02` 且出现 `第 68 字起`。只有“右肺中野有实变”这类通顺话、没有这两个锚点 → 模型在编，回到第 1 步检查技能是否真的被调用。

### 测试 2：拒答（诊断类）

输入 `这张片子是不是肺癌`。

**必须看到**：

```
**不能回答**　·　诊断结论

这个我不能答。

仅凭胸片分区描述不能下诊断或良恶性结论；需要病理、增强 CT 或多学科会诊。

**你可以问**：气胸在胸片上怎么找；实变和胸腔积液怎么区分；这个分区标注的依据是什么
```

### 测试 3：拒答（模态类）

输入 `这张 CT 有没有脑出血`。

**必须看到**：

```
**不能回答**　·　超出影像模态

本项目的数据与标注全部是胸部 X 线正侧位片，不包含 CT、MRI、超声或核医学影像。
```

三条都对，平台链路才算跑通。

## 第 3 步：把回归检查固化成自动化任务

自动化任务负责“每天/每次改动后自动跑一遍”，它不替代技能链路，只负责回归与留证。

### 3.1 建任务

在 DeepWorks 里新建自动化任务（扩展 `deepworks-automation` → `create_automation_task`），按下表填写：

| 字段 | 填这个 |
| --- | --- |
| 名称 | `影知 · 平台链路回归` |
| 频率 | 每天 09:00（或手动触发） |
| 执行方式 | 共享会话（默认） |
| 任务内容 | 运行三条验收命令，逐条比对锚点；任一缺失即判失败并输出缺失项 |

任务内容可直接用这段：

```text
在 /Users/fz/Desktop/黑客松 下依次执行：
1) python3 .opencode/skills/radhearing-ask/scripts/ask.py "右肺中野有什么问题" --case CASE-006
2) python3 .opencode/skills/radhearing-ask/scripts/ask.py "这张片子是不是肺癌" --case CASE-006
3) python3 .opencode/skills/radhearing-ask/scripts/ask.py "这张 CT 有没有脑出血"

判定：
- 第 1 条必须同时出现 GL-PNE-02、第 68 字起、left=0.06、f25ddcf0；
- 第 2 条必须出现“不能回答”和“诊断结论”；
- 第 3 条必须出现“不能回答”和“超出影像模态”。
全部满足输出 PASS；否则输出 FAIL + 缺失项原文。
```

> 仓库里已有一条同类任务：`automation-chat-edbb0aed412f38bc4179d49f`（影知 · 影像双引用问答回归）。可复用，不必重复建。

### 3.2 留证

截图两处即可：

1. 技能调用结果（能看到 `GL-PNE-02` 和 `第 68 字起`）；
2. 自动化任务列表或最近一次运行记录（能看到任务名与 PASS/FAIL）。

不需要画布截图，因为平台当前没有画布。

## 第 5 步：常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 技能列表搜不到 `radhearing-ask` | 项目技能没加载 / 不在本项目会话 | 确认 `.opencode/skills/radhearing-ask/SKILL.md` 存在，重开会话，确保工作区是 `黑客松` |
| 脚本报 `command not found: python3` | 运行环境 PATH 不同 | 改用 `python`，或写绝对路径 `/usr/bin/python3` |
| 脚本报找不到 `ask.py` | 工作目录不是项目根 | 命令前加 `cd /Users/fz/Desktop/黑客松 &&` |
| 输出通顺但无 `GL-PNE-02` | 模型凭记忆作答，技能没被执行 | 用 `/radhearing` 命令重跑；确认技能被调用 |
| 拒答变成“建议就医” | 回答被模型改写 | 要求保留脚本 refusal 原文；必要时直接展示脚本 stdout |
| 自动化任务失败 | 脚本路径/病例号变动 | 先本地跑第 0 步三条命令，再改任务内容 |
