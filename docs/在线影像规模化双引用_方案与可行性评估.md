# 在线公开影像的规模化「区域定位 + 文献溯源双引用」

> 版本：v1.0 ｜ 日期：2026-11-15 ｜ 承接 [影像区域定位与双引用设计](影像区域定位与双引用设计.md) v1.1
> 主题：把「3 张人工标注图」扩到「在线公开影像的广泛、即时双引用」，并评估其合理性与可行性
> 实测数据来源：Wikimedia Commons API / Europe PMC API，探测时间 2026-11-15（见 §10）

---

## 0. 结论摘要

**能做，但必须先改掉「广泛即时」的定义。**

| 判断 | 结论 |
| --- | --- |
| 技术路线 | 成立。核心是把「每图人工标注」换成「通用模板 + 图像配准」，定位从**资产**变成**变换** |
| 规模化 | 部分成立。公开源可支撑**千级**候选引用，**万级可信引用必须接机构数据** |
| 「即时」 | 成立，但含义是「即时给出**分级结果**」，不是「即时产出可信结论」 |
| 最大风险 | 不是算法，是**合规**与**复核预算**：自动结论会被误读为诊断，自动引用会伪造出处 |
| 关键设计 | 五态门禁 + 证据等级 + claim 模板化。三者缺一，规模化就会污染知识库 |

一句话：**把「可信」从模型输出搬到门禁判定，把「规模」从标注数量搬到模板复用。**

## 1. 需求拆解：四个词互相冲突

用户原话里的四个关键词，各自成立，合在一起就冲突：

| 词 | 真实含义 | 与其它词的冲突 |
| --- | --- | --- |
| **大量** | 万级影像 | 与「可信」冲突：可信靠人工复核，人力是线性成本 |
| **在线** | 动态抓取、非预置 | 与「许可」冲突：NC/ND 图不能内嵌；与「稳定」冲突：链接会失效 |
| **广泛** | 任意影像都能用 | 与「定位」冲突：超声/内镜/病理无统一空间参考 |
| **即时** | 用户贴图即出结果 | 与「溯源」冲突：文献锚点需要抽取与核验，无法零延迟 |

所以方案的第一步不是选技术，而是**给每个词划边界**：

```
大量   → 万级「候选」，千级「可信」
在线   → 采集入库（受控），不是运行时抓任意 URL
广泛   → 覆盖「标准体位的 2D 投影影像」，其余降级为 local / 拒绝
即时   → 秒级出「定位候选 + 引用候选 + 证据等级」，可信结论异步升级
```

> 这不是妥协，而是医学知识库的常规做法：**证据分级**本身就是「广泛」与「可信」的调和机制。

## 2. 现状差距：v1.1 为什么不能直接扩

现有实现的可信度来自三件事，每一件都不可扩展：

| 现状 | 数量 | 扩展瓶颈 |
| --- | --- | --- |
| 病例 | 32 例 | 每例要人工核许可、隐私、来源 |
| 分区标注 | 21 个 / 3 张图 | **每张图单独标**，一张 15–30 分钟 |
| 双引用结论 | 7 条 | 每条要人工绑定分区 + 条款 + 摘录 hash |

按当前模式，1 万张图需要约 **3,000–5,000 人时**（≈ 2 人年）。这不是工程问题，是模式问题。

**必须换掉的假设**：`region` 属于「这张图」。
**要换成的假设**：`region` 属于「这个体位模板」，图只是模板的一次实例。

这一条改动，把标注成本从 `O(图像数)` 降到 `O(体位模板数)`。

## 3. 总体架构：五层 + 一条原则

```
┌─ L0 采集准入 ────────────────────────────────────────────┐
│ provider 注册 → 许可解析 → 隐私筛查 → 去重 → 入库队列      │
│ 输出：image_record（含 license / provenance / caption）   │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌─ L1 体位归一 ────────────────────────────────────────────┐
│ 元数据优先（DICOM ViewPosition）→ 分类器兜底               │
│ 输出：pose_class + pose_confidence；不达标 → 直接 no_atlas │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌─ L2 空间定位 ────────────────────────────────────────────┐
│ R1 继承标注 │ R2 模板配准 │ R3 解剖分割 │ R4 图文定位      │
│ 融合裁决 → region_binding（method / transform / 残差）     │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌─ L3 知识绑定 ────────────────────────────────────────────┐
│ claim 模板（region_type × sign × clause）→ 槽位实例化      │
│ 禁止自由生成；引用由三元组决定，不由模型选                  │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌─ L4 引用门禁 ────────────────────────────────────────────┐
│ 原四门（存在/完整/hash/时效）+ 新三门（许可/溯源/一致性）   │
│ 输出五态：dual_verified / dual_provisional / single /     │
│           broken / link_only                              │
└──────────────────────────┬───────────────────────────────┘
                           ▼
┌─ L5 呈现审计 ────────────────────────────────────────────┐
│ 分区叠加（实线=人工 / 虚线=自动）+ 双引用胶囊 + 证据角标    │
│ 审计看板：按 method / confidence / 失败原因 分组            │
└──────────────────────────────────────────────────────────┘
```

**贯穿原则：只降级，不升级。** 任何一层拿不准，结果只能往低可信走，不能靠「其他层看起来没问题」把它抬上去。这条原则决定了规模化不会放大错误。

## 4. 关键设计一：把「标注」变成「变换」

这是整个方案的技术核心。

### 4.1 模板与实例分离

```json
// kb/data/pose_templates.jsonl —— 新增，O(体位) 而非 O(图像)
{
  "id": "TPL-CHEST-PA-6",
  "name": "胸片六分区模板（PA）",
  "modality": ["CR", "DX"],
  "pose_class": "chest_pa",
  "reference_image": "templates/chest_pa_ref.jpg",
  "reference_size": [1024, 1024],
  "landmarks": [
    {"id": "trachea_mid", "xy": [0.50, 0.18]},
    {"id": "carina", "xy": [0.50, 0.34]},
    {"id": "diaphragm_r", "xy": [0.34, 0.72]},
    {"id": "diaphragm_l", "xy": [0.66, 0.72]},
    {"id": "costophrenic_r", "xy": [0.20, 0.78]},
    {"id": "costophrenic_l", "xy": [0.80, 0.78]}
  ],
  "regions": [
    {"key": "RUL", "name": "右肺上野", "coords": [0.09, 0.10, 0.39, 0.18], "patient_side": "right"},
    {"key": "RML", "name": "右肺中野", "coords": [0.09, 0.32, 0.39, 0.24], "patient_side": "right"},
    {"key": "RLL", "name": "右肺下野", "coords": [0.09, 0.58, 0.39, 0.16], "patient_side": "right"},
    {"key": "LUL", "name": "左肺上野", "coords": [0.56, 0.10, 0.35, 0.18], "patient_side": "left"},
    {"key": "LML", "name": "左肺中野", "coords": [0.56, 0.32, 0.35, 0.24], "patient_side": "left"},
    {"key": "LLL", "name": "左肺下野", "coords": [0.56, 0.58, 0.35, 0.16], "patient_side": "left"}
  ],
  "laterality_rule": "pa_chest: image_left = patient_right",
  "annotator": "human",
  "annotated_at": "2026-11-15"
}
```

模板只标一次，之后所有同体位图复用。分区坐标仍用归一化 `[x,y,w,h]`，与现有 `regions.jsonl` 完全兼容。

### 4.2 三级配准，按成本递进

| 级别 | 方法 | 依赖 | 精度 | 成本 |
| --- | --- | --- | --- | --- |
| P1 | **3 点相似变换**（气管中点 + 左右膈顶） | 无模型，OpenCV `estimateAffinePartial2D` | 中 | < 10 ms |
| P2 | **6–16 关键点 + 仿射** | 关键点检测模型或模板匹配 | 较高 | 50–150 ms |
| P3 | **B 样条弹性配准**（归一化互信息） | SimpleITK / ITK | 高 | 0.5–2 s |

**黑客松只需要 P1**：胸片 PA 体位标准化程度高，3 个点足以把六分区落到合理位置。P3 留给旋转、吸气不足、明显变形的片子。

### 4.3 残差即门禁

```
residual = mean(‖landmark_pred - landmark_ref‖) / image_width
```

| 残差 | 处理 |
| --- | --- |
| < 3% | 可用于 `dual_provisional` |
| 3%–6% | 仅展示分区，不绑定 claim |
| > 6% | 判定 `no_atlas`，禁用框选 |

残差不是调试信息，是**产品可见字段**。界面上要写「自动定位，残差 2.1%，待复核」，而不是假装它和人工标注一样准。

### 4.4 为什么这条路线成立

- 体位是**有限集合**：胸 PA/AP、胸侧位、膝正侧位、手正位、头颅轴位、乳腺 MLO/CC —— 20 个模板覆盖绝大多数教学场景
- 2D 投影影像的解剖位置由**投照几何**决定，个体差异是「形变」而非「拓扑变化」，仿射 + 轻度弹性足够
- 不需要病灶检测，不需要训练数据，不需要器械资质 —— 与原设计的能力边界一致

## 5. 关键设计二：四路定位 + 融合裁决

单一方法在规模化时必然遇到长尾，所以并行四路，互为校验。

| 路 | 输入 | 输出 | 可信度 | 适用 |
| --- | --- | --- | --- | --- |
| **R1 继承标注** | 图上已有 overlay / 箭头 / 文字 | 直接登记「图上已标」 | 高（人标的） | Commons annotated 图、Radiopaedia 箭头图 |
| **R2 模板配准** | pose_class + 模板 | transform + 分区 bbox | 中高 | 标准体位，主力 |
| **R3 解剖分割** | 分割模型（TotalSegmentator / MedSAM2） | 器官 mask | 中 | CT/MR；2D 需投影映射 |
| **R4 图文定位** | caption 中的解剖短语 | 分区名（无几何） | 低 | 仅作仲裁，不单独出框 |

### 5.1 融合规则（写死、可单测）

| 组合 | 裁决 |
| --- | --- |
| R2 成功 + R4 一致 | `dual_provisional`，置信度 +0.1 |
| R2 成功 + R4 矛盾（如 caption 写 left，几何判 right） | **降级 `single`**，标记「图注与几何不一致」 |
| R2 失败 + R3 成功 | 用 R3 的器官 mask 映射分区，标 `method: segmentation` |
| R2 失败 + R3 失败 + R4 有分区名 | 只给文字分区，`single`，无空间锚点 |
| 全部失败 | `no_atlas`，禁用框选 |

**R4 的价值不是定位，是抓矛盾。** 自动化的最大风险是「自信地错」，而图注是唯一独立于几何的第二信源。

## 6. 关键设计三：claim 模板化，禁止自由生成

规模化最大的诱惑是「让模型看图写结论」。这条路必须堵死，原因有三：

1. **会伪造引用**：模型会写出「依据 ACR Lung-RADS 4A」，但条款里没有这句话，hash 门必拦
2. **会越界**：从「密度增高影」滑到「考虑肺炎」，触碰合规红线
3. **不可复现**：同一张图两次生成不同结论，审计无法回放

### 6.1 模板结构

```json
// kb/data/claim_templates.jsonl —— 新增
{
  "id": "CTPL-LUNG-CONSOL",
  "region_type": "lung_zone",
  "sign_ids": ["SIGN-002"],
  "guideline_ids": [],
  "template": "{region_name}区域可见{sign_name}（{sign_excerpt}）。本条目为表现对照，不构成诊断。",
  "requires": ["sign_excerpt_sha256"],
  "max_evidence": "D2"
}
```

实例化时只允许填库内字段，槽位值全部来自 `signs.jsonl` / `guidelines.jsonl`，并带上各自的 hash。

### 6.2 三条硬约束

| 约束 | 检查方式 |
| --- | --- |
| 槽位只能来自库内 | 渲染前断言每个槽位值在源记录中存在 |
| 不新增事实 | 模板外不追加句子；`text` 必须能由模板 + 槽位完整重建 |
| 引用由三元组决定 | `(region_type, sign_id, guideline_id)` 唯一映射到 `cites`，模型不参与选择 |

这样规模化的是**数据工程**，不是**模型能力**。1,000 条 claim 与 7 条 claim 的可信度机制完全相同。

## 7. 关键设计四：五态门禁

原设计的三态（dual / single / broken）在规模化下不够用，因为多了两个新失败模式：**不能展示**（许可）和**出处不真**（转载）。

### 7.1 新增三道门

| # | 门 | 规则 | 失败处理 |
| --- | --- | --- | --- |
| 5 | **许可门** | 图像许可 ∈ {CC0, PD, CC BY, CC BY-SA} 才可内嵌；NC/ND/未知 → 只存链接 | `link_only`，不生成空间锚点 |
| 6 | **溯源门** | `page_url` 必须是原始托管方（Commons file page / PMC / 机构库 / DOI）；聚合站、转载站不算 | 降级 `link_only`，并记录转载链 |
| 7 | **一致性门** | caption 的侧别/部位/模态 vs 几何定位结果 | 矛盾 → `broken`（不是 `single`） |

第 7 道是自动化的安全阀：**几何说右、图注说左，这种矛盾绝不能靠置信度投票解决，只能拦。**

### 7.2 五态定义

| 状态 | 空间锚点 | 文献锚点 | 人工复核 | 界面 | 计入「可信」 |
| --- | --- | --- | --- | --- | --- |
| `dual_verified` | 人工 / 自动+抽检 | D2 或 D3 | 是（对应角标 A/B） | 实线框 + 绿胶囊 | ✅ |
| `dual_provisional` | 自动 | D1 或 D2 | 否 | 虚线框 + 琥珀胶囊 +「自动定位·待复核」 | ❌ |
| `single` | 仅一侧 | 仅一侧 | — | 单胶囊 + 缺项删除线 | ❌ |
| `broken` | 校验失败 | 校验失败 | — | 折叠 + expected/actual | ❌ |
| `link_only` | 无（不可展示） | 仅链接 | — | 外链卡片，无图 | ❌ |

**`dual_provisional` 是本方案的关键发明**：它让「规模」和「诚实」同时成立——系统可以立刻给出约 580 条带锚点的条目，但只有约 116 条计入可信统计。评审问「你这 580 条靠谱吗」，答案是「580 条候选、116 条已复核，其余每条都标了待复核」。

### 7.3 文献锚点也要分级

在线影像的「文献」往往只是图注，不能和指南条款平权：

| 等级 | 类型 | 例 | 能证明什么 | 允许的最高状态 |
| --- | --- | --- | --- | --- |
| **D1** | 图注 / 来源自述 | Commons `ImageDescription` | 「这张图被这样描述」 | `dual_provisional` |
| **D2** | 病例 / 论文段落 | PMC 全文中的 case 描述 | 「这个病例有这段记录」 | `dual_verified` |
| **D3** | 指南 / 标准条款 | ACR TI-RADS TR4 | 「这类表现有这条标准」 | `dual_verified` |

这条分级直接堵住一个常见偷换：**用图注冒充指南背书**。界面上必须显示 `D1 来源自述` / `D3 指南条款`，不能都叫「文献」。

## 8. 关键设计五：「即时」的真实含义

| 时点 | 系统做什么 | 用户看到 |
| --- | --- | --- |
| T+0 | 入库、算 pHash、解析许可与图注 | 「已收录，待定位」 |
| T+0～2 s | 体位判定 → 模板配准 → 分区 → claim 实例化 → 七门校验 | 分区虚线 + 双引用胶囊 + 证据角标 |
| T+异步 | 人工抽检 / 复核 | 角标从 `C` 升到 `B` / `A` |
| T+定时 | 复抓 URL、校验 hash、检查版本 | 失效条目自动降级 |

**「即时」承诺的是「2 秒内给出可核验的候选」，不是「2 秒内给出可信结论」。** 这个措辞差异必须在文档、界面、答辩口径里保持一致，否则会被追问「自动生成的也敢叫双引用？」

### 8.1 证据角标

| 角标 | 含义 | 判据 |
| --- | --- | --- |
| **A** | 人工双复核 | 分区与引用均经两人确认，IoU ≥ 0.7 |
| **B** | 自动 + 抽检通过 | 自动定位，落在抽检样本内且无错 |
| **C** | 仅自动 | 未复核，界面必须显示「待复核」 |
| **D** | 仅浏览 | 无 atlas 或无文献，只能看图 |

角标放在缩略图和详情页两处，且进入检索排序权重 —— 这样「规模」不会稀释「可信」。

## 9. 数据模型增量（与现有 kb 对齐）

不改现有四个核心文件的结构，只加字段、加新文件。

### 9.1 `cases.jsonl` 增字段

```json
{
  "provenance": {
    "origin_page": "https://commons.wikimedia.org/wiki/File:...",
    "origin_domain": "commons.wikimedia.org",
    "retrieved_at": "2026-11-15",
    "repost_chain": [],
    "is_origin": true
  },
  "pose_class": "chest_pa",
  "pose_confidence": 0.93,
  "pose_source": "dicom_tag | classifier | caption",
  "content_class": "clinical_human | historical | animal | industrial | diagram",
  "evidence_level": "C",
  "batch_id": "BATCH-2026-11-15-A"
}
```

`content_class` 是新增的关键字段：实测显示 Commons 的 x-ray 搜索结果里混有 1895 年历史照片、动物、手机工业检测图（见 §10.3），**必须在入库时分开**，否则定位与引用都会被污染。

### 9.2 `regions.jsonl` 增 `derivation`

```json
{
  "id": "REG-ONL-000123-RML",
  "image_id": "ONL-000123",
  "atlas_id": "TPL-CHEST-PA-6",
  "name": "右肺中野",
  "coords": [0.09, 0.32, 0.39, 0.24],
  "image_side": "left",
  "patient_side": "right",
  "derivation": {
    "mode": "template",
    "template_id": "TPL-CHEST-PA-6",
    "transform": [[1.02, 0.01, -0.03], [-0.01, 0.98, 0.05]],
    "residual": 0.021,
    "landmarks_used": 3,
    "method": "affine_partial",
    "confidence": 0.86
  },
  "verify_status": "auto"
}
```

保留 `coords` 为最终归一化框，`derivation` 只记录「怎么来的」。这样渲染层完全不用改。

`verify_status` 三值直接对应证据角标：`auto` → C、`spot_checked` → B、`double_read` → A。

### 9.3 新增文件

| 文件 | 内容 | 规模 |
| --- | --- | --- |
| `kb/data/pose_templates.jsonl` | 体位模板 + 关键点 + 分区定义 | 20 套以内 |
| `kb/data/claim_templates.jsonl` | claim 模板 | 50–100 条 |
| `kb/data/citations.jsonl` | 引用独立成表（从 claim 拆出） | 与 claim 1:N |
| `kb/data/sources_registry.json` | provider 能力矩阵（许可/图注/API/限流） | 10 个以内 |
| `kb/data/ingest_queue.jsonl` | 待核验队列（已有 `_candidates/online_queue.jsonl`，合并） | 动态 |

**为什么把 `cites` 从 `claims` 拆出来**：引用会独立失效（URL 404、条款改版、许可变更），拆表后可以单独重检、单独降级，不用重写整条 claim。这是规模化的必要解耦。

### 9.4 新增脚本与服务

| 路径 | 职责 |
| --- | --- |
| `kb/scripts/ingest_online.py` | 采集 → 许可/隐私/内容分类/去重 → 入队 |
| `kb/scripts/fit_template.py` | 体位判定 + 三级配准 + 残差计算 |
| `kb/scripts/extract_citation.py` | 图注/条款抽取 → D1/D2/D3 分级 → hash |
| `kb/scripts/verify_citations.py` | 七门校验 + 五态判定（可定时跑） |
| `kb/scripts/serve_region.py` | 扩 3 个接口（见下） |

```

POST /api/bind   { image_id }           触发定位 + 绑定，返回五态结果

```

## 10. 实测：公开影像源的真实可用密度

这一节是可行性评估的事实基础。所有数字为 2026-11-15 实际 API 探测结果。

### 10.1 数量：够

| 探测 | 结果 |
| --- | --- |
| Commons `filetype:bitmap x-ray` | **60,544** |
| Commons `filetype:bitmap radiograph` | **52,558**（与上者有重叠） |
| Commons `filetype:bitmap "computed tomography"` | 3,766 |
| Commons `filetype:bitmap ultrasound medical` | 2,252 |
| Commons `filetype:bitmap mammogram` | 128 |
| Europe PMC 开放全文（`OPEN_ACCESS:Y AND HAS_FT:Y AND SRC:PMC`） | 433,941 篇 |

数量级成立：**10⁴ 级影像 + 10⁵ 级全文**。文献侧不缺，影像侧够用。

### 10.2 许可：Commons 几乎全通过

对 `Category:X-rays of normal chest` 全部 26 张取 `extmetadata`：

| 许可 | 张数 | 占比 |
| --- | --- | --- |
| CC BY-SA 3.0 | 11 | 42% |
| CC0 | 7 | 27% |
| CC BY-SA 4.0 | 3 | 12% |
| CC BY 3.0 | 3 | 12% |
| Public domain | 1 | 4% |
| CC BY 4.0 | 1 | 4% |

**100% 落在白名单内**（现有白名单已含 BY-SA）。这说明：在 Commons 场景，许可不是瓶颈；真正的瓶颈在内容与体位。但要注意 BY-SA 的传染性 —— 内嵌展示可以，打包分发要整体同许可。

### 10.3 密度：这是真正的瓶颈

三个反直觉的实测结果：

**(a) 「正常解剖」分类极小。** `Category:X-rays of normal anatomy` 有 32 个子分类，但所有子分类的直接文件合计只有 **119 张**（胸部 26、足侧位 18、足正位 16、膝 15、踝 11……）。

**(b) 体位元数据几乎不存在。** 随机抽 50 张 `filetype:bitmap x-ray`，标题含 PA/AP/lateral/axial 等体位词的只有 **1 张（2%）**。而标题是 Commons 唯一稳定的结构化线索。

**(c) 搜索结果混入大量非临床影像。** 同一批 50 张抽样里出现：伦琴 1895 年历史照片、龙猫肾结石 X 光、诺基亚 N97 手机工业 X 光、骨龄软件演示图。含日期/年龄（触发隐私标记）3 张（6%）；临床人体影像约 29 张（58%），其余为历史、动物、工业与示意图。

**(d) 接口稳定性。** Open-i API 本次探测返回错误页；官方口径为 370 万+ 影像，但**当前不可直接依赖**。

结论：**「大量公开影像」在数量上成立，在「可用于解剖定位」上极其稀疏。** 规模化的难点不是抓不到图，是抓到的图里能定位的比例低。

### 10.4 漏斗：从 1 万张候选到多少条可信引用

以 10,000 张候选为输入，按实测与保守估计逐层衰减：

| 层 | 通过率 | 剩余 | 依据 |
| --- | --- | --- | --- |
| 候选入库 | 100% | 10,000 | — |
| 临床人体影像（排除历史/动物/工业/示意图） | 40% | 4,000 | §10.3(c) 抽样临床约 58%，保守取 40% |
| 许可白名单 | 95% | 3,800 | §10.2 实测（Commons 内近 100%，留 5% 余量） |
| 去重（pHash + 标题） | 85% | 3,230 | 转载普遍 |
| 体位可判定（元数据或分类器） | 55% | 1,777 | §10.3(b)：元数据缺失，靠分类器补 |
| 模板配准残差 < 3% | 70% | 1,244 | P1/P2 配准经验值 |
| 文献锚点可得（D1 及以上） | 55% | 684 | 图注覆盖率 |
| 一致性门通过 | 85% | **581** | 图注与几何矛盾率 |
| **→ `dual_provisional`** | **5.8%** | **581** | 可立即展示 |
| 人工复核 20% | — | **116** | 升 `dual_verified` |

**关键推论**：

- 1 万张候选 → **581 条 provisional**；抽 20% 复核（116 条）→ **116 条 verified**
- **verified 的成本与采集量解耦**：复核条数 ≈ 目标 verified 条数，每条 60–90 s。1,000 条 verified ≈ **21 人时**（约 3 人日）
- 但 **provisional 池子受候选量限制**：要 1,000 条 verified，若抽检 20%，需 5,000 条 provisional → 约 10 万张候选
- Commons 全部 x-ray（6 万）中人体临床约 2.4 万 → provisional 上限约 **3,500 条**；全量复核可得 3,500 条 verified，约 73 人时

**所以「万级可信引用」在纯公开源上做不到，必须叠加机构数据。** 限制不在人力（万级复核约 26 人日，完全可负担），而在**公开影像的可定位密度**：6 万张 x-ray 只够支撑 3,500 条左右。

## 11. 可行性评估

### 11.1 六维打分

| 维度 | 分（1–5） | 判断依据 |
| --- | --- | --- |
| 技术可行性 | **4** | 模板配准、关键点检测、hash 校验都是成熟技术；无自研模型依赖 |
| 数据可得性 | **3** | 数量够（6 万），密度低（可定位约 6%）；Open-i 接口不稳 |
| 许可合规 | **4** | Commons 干净；Radiopaedia/e-Anatomy 只能外链；BY-SA 有传染性 |
| 临床与监管风险 | **2** | 自动结论易被误读为诊断；必须靠文案、角标、门禁三重约束 |
| 工程可控性 | **4** | 增量改造，不改现有 schema 主干；可单测、可回放 |
| 成本 | **5** | 算力 < ¥1,000 / 万张；真正成本是人工复核 |
| 用户价值 | **5** | 「可核验」是知识库相对通用大模型的核心差异 |

**综合：合理，但属于「中等风险、需要克制」的功能。** 不是不能做，是不能按「全自动」做。

### 11.2 成本结构

以 1 万张候选为一批：

| 项 | 单价 | 小计 |
| --- | --- | --- |
| 模板配准（CPU） | 0.2 s/张 | 33 分钟单核 |
| 关键点检测（GPU，可选） | 0.1 s/张 | 17 分钟 |
| 图注/条款抽取（LLM） | ~8 s/条 | 22 小时，约 ¥300–800 |
| 缩略图存储 | 200 KB/张 | 2 GB |
| 人工复核（581 条的 20% = 116 条） | 60–90 s/条 | ~2.4 人时 |
| 模板标定 + 异常排查 | — | ~2 人日 |
| **合计** | — | **≈ 2–3 人日 + ¥1,000 以内** |

**结论：钱不是约束，人天是约束；但人天可以抽检摊薄。** 复核成本 ≈ 目标 verified 条数 × 75 s，与采集量无关——这解释了为什么方案要把「复核」做成可增量、可抽检的流水线，而不是一次性全量。

### 11.3 五个不成立的假设

必须明确写出来，否则团队会按错误预期排期：

| 假设 | 为什么不成立 | 替代做法 |
| --- | --- | --- |
| 「任意在线图片都能定位」 | 只有标准体位的人体临床 2D 影像可配准；超声/内镜/病理无统一空间参考 | 体位门 + `local` 降级 + 拒绝 |
| 「模型看图写结论再自动配引用」 | 会伪造引用（hash 必拦）、会越界、不可复现 | claim 模板化，槽位只填库内字段 |
| 「许可可以事后处理」 | NC/ND 内嵌即侵权，下架成本远高于前置过滤 | 许可门前置，只存链接 |
| 「分割模型能替代解剖分区」 | 分割给器官 mask，不给「右肺中野」这类教学分区 | mask → 分区映射表 |
| 「规模上来后可以不要人工」 | 复核是线性成本，且是唯一能把 C 升到 A 的手段 | 分层抽检 + 证据角标 |

### 11.4 合理性：该不该做

**该做，理由三条**：

1. **差异化在这里**：通用大模型能给结论但不能给「图上哪块 + 文献哪条」，双引用是知识库的护城河
2. **路径是渐进的**：模板化与现有 `atlases/regions/claims` 完全兼容，不是重写
3. **风险可控**：五态门禁让「不确定」变成可见状态，而不是隐藏错误

**但要接受一个前提**：这个功能的价值不在「覆盖多少张图」，而在「每一条都能被核对」。如果为了规模牺牲门禁，它会退化成「带链接的看图说话」，反而不如不做。

## 12. 风险与红线

| 风险 | 触发信号 | 处置 |
| --- | --- | --- |
| 自动定位在异常体位失效 | 残差 > 6% 比例 > 20% | 收紧体位门；P1 升 P3；该体位降级 `local` |
| 图注与几何矛盾被忽略 | 一致性门拦截率异常低 | 抽查 50 条人工核对；矛盾必须 `broken` |
| 转载站冒充原始出处 | `origin_domain` 不在白名单 | 溯源门 → `link_only`；记录转载链 |
| 许可误判 | 抽检发现 NC 图内嵌 | 许可快照存档 + 双人复核高风险源 |
| 隐私泄漏 | 图内出现姓名/日期/编号 | 双重筛查 + 只存缩略图 + 支持撤回 |
| 被误读为 AI 诊断 | 用户问「这是不是自动诊断」 | 文案禁用「检出/诊断」；`provisional` 不进结论区；固定声明 |
| 复核预算失控 | 队列积压 > 2,000 | 分层抽检：高风险 method 全检，低风险抽 10% |
| 链接失效 | 定时复检 404 | 存 excerpt + hash + 抓取时间；失效降级「快照可查」 |
| 规模上去后审计不可读 | 审计页加载 > 3 s | 聚合视图 + 按 method/confidence 分桶 |

**三条红线**（不可协商）：

1. 不输出诊断结论、不建议治疗、不给分期
2. 不用模型生成文献摘录；摘录必须来自原文并带 hash
3. 不可展示的图（NC/ND/未知许可）不生成空间锚点

## 15. 一页答辩口径

> 我们不是让模型看图下诊断，而是让**每一张公开影像都能被追问「说的哪儿、凭的哪条」**。
>
> 定位靠**体位模板 + 图像配准**，不靠逐张手标，所以能上规模；引用靠**七道门禁**，不靠模型自觉，所以敢标等级。
>
> 在线抓来的图，2 秒内给出分区候选和引用候选，同时给出 A/B/C/D 证据角标。C 级明确写「自动定位·待复核」，不进可信统计。
>
> 实测 6 万张公开 X 光里，能自动定位的约 6%。所以我们不承诺「所有图都能双引用」，只承诺**「标了双引用的，你都能点开核对」**。
