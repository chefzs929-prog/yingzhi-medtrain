## 0. 一句话定位

**区域定位**把「用户在图上看的那块地方」翻译成「解剖分区 + 该分区可对照的知识」；
**双引用**要求每条结论同时挂上**空间锚点**（图上哪一块）和**文献锚点**（哪份文献哪一条），缺一条就降级、校验不过就隐藏。

两者合起来回答一句评委一定会问的话：**你凭什么这么说，说的又是哪儿？**

## 1. 为什么需要这两个功能

现有 `kb/` 已能按征象检索、能做影像线与指南线双线对齐，但链路里有两个断点：

| 断点 | 现状 | 后果 |
| --- | --- | --- |
| 入口断点 | 用户只能输入文字提问 | 医生看着图说话，文字描述丢失空间信息；「右上肺那块」打成字就变成模糊查询 |
| 出口断点 | 引用只有文献侧 | 结论能回溯到条款，但回不到「图上哪一块」，无法核对结论与影像是否对得上 |

这两个断点不是 UI 问题，是**数据结构缺两个字段**：影像侧缺 `region`，引用侧缺 `spatial`。
所以核心工作量在 schema 与校验，不在界面。

## 2. 能力边界（先写清楚不做什么）

| 不做 | 原因 | 界面表现 |
| --- | --- | --- |
| 不做病灶检测 / 分割 | 需要训练数据与器械资质，与「教学研究」定位冲突 | 分区框是**人工标注**的解剖区，不是模型输出的病灶轮廓 |
| 不判断框内是不是病变 | 同上 | 文案只用「该分区可对照的征象」，不用「检出」「提示病变」 |
| 不给诊断结论 | 合规底线 | 固定声明常驻；不输出「癌」「建议手术」等表述 |
| 不做自动测量 | 无 DICOM 像素标定 | 不显示 cm / mm，只显示相对位置与覆盖度 |
| 不给未标注分区编造位置 | 宁可说不知道 | 29 条未标注病例显式标「待标注」，框选直接提示不可定位 |

**一句话**：定位的是**解剖区域**，不是**病灶**。这句话同时出现在文档、界面和答辩里。

## 3. 功能一：影像区域定位（Region Locate）

### 3.1 三级粒度

| 级别 | 内容 | 数据来源 | 示例 |
| --- | --- | --- | --- |
| L1 部位 | 胸部 / 头颈 / 乳腺 / 腹部 / 肌骨 | `taxonomy.json` | `REG-CHEST` |
| L2 解剖分区 | 图内可指认的解剖区 | `regions.jsonl`，人工标注 | `REG-CHEST-RML` 右肺中野 |
| L3 影像组 | 该分区的表现族 | `groups.jsonl` | `GRP-LUNG-CONSOLIDATION` |

三级是逐级收窄的过滤链，不是三套独立检索。

### 3.2 Atlas 能力分级

不同模态的定位可信度差别很大，必须分级：

| 等级 | 含义 | 适用 | 输出 |
| --- | --- | --- | --- |
| `global` | 有全身解剖参考，可给标准分区与侧别 | PA/AP 胸片、头颅 CT/MR、腹部 CT | 解剖名 + 患者侧别 |
| `local` | 只有局部视野，只能给图像内相对位置 | 超声、钼靶局部加压位 | 「图像中央区 / 周边腺体」，**不给左右叶** |
| `none` | 无可靠空间参考 | 定位像、示意图、多图拼接 | 只给整图，禁用框选 |

v1.1 的甲状腺超声（`CASE-011`）按 `local` 处理：界面明确写「局部视野：只给图像内相对位置，不推断解剖左叶/右叶」。
这是**诚实的能力声明**，比硬编一个「左叶」更能说明设计想清楚了。

### 3.3 四种交互入口

| 入口 | 操作 | 适用 |
| --- | --- | --- |
| 拖框 | 在图上拖出矩形 | 主路径，「我想看这块」 |
| 点定位 | 单击某点 | 快速看分区名；取点所在**最小**分区，避免大区盖住小区 |
| 悬停预览 | 鼠标移动显示分区名 | 教学、答辩演示，不触发检索 |
| 文本定位 | 点「右肺中野」等分区名 | 框不准时的兜底 |

### 3.4 匹配算法

```
A        = area(bbox ∩ region)
coverage = A / area(bbox)      # 框内有多少落在该区
purity   = A / area(region)    # 该区有多少被框住
score    = 0.7 * coverage + 0.3 * purity
```

判定分支（阈值写死、可单测）：

| 条件 | 输出 | 理由 |
| --- | --- | --- |
| `top1 - top2 ≥ 0.15` | `single` 单一主分区 | 明确命中 |
| `top1 - top2 < 0.15` 且次候选 `coverage > 0.25` | `cross` 跨区，并列候选 | 边界附近不硬猜 |
| `max coverage < 0.35` | `uncovered` | 宁可说不知道 |
| 任一边长 < 1.5% | `too_small` | 小框几何噪声大，且与「区域」语义不符 |
| 选区面积 > 60% | `too_large` | 大框会同时命中多个区，等于没定位 |
| 该图无 atlas | `no_atlas` | 未标注即不推断 |

**为什么 coverage 主导**：用户框的是「我想问的地方」，框内内容比分区被覆盖的比例更贴近意图。`purity` 只作次要修正，防止「一个大框罩住半张图」拿满分。

### 3.5 侧别安全（最容易错、也最值得讲）

图像坐标的左右**不等于**患者左右：

- PA / AP 胸片：图像左侧 = 患者**右侧**（`CASE-001` 左上角 `Dx` 即右标记）
- 轴位 CT/MR：图像左侧 = 患者**右侧**
- 乳腺 MLO：需看图上 `R` / `L` 标记，不能按方位推
- 侧位片：无左右之分，只有前后

因此 schema 里**图像侧与患者侧是两个字段**，由 `laterality_rule` 显式声明：

```json
{ "image_side": "left", "patient_side": "right",
  "laterality_rule": "pa_chest: image_left = patient_right" }
```

界面同时显示：`右肺中野（患者右侧）` + `图像左侧 · pa_chest: image_left = patient_right`。
25 项测试里有一项专门遍历全部分区做映射一致性断言，**零容忍**。

### 3.6 定位卡输出

```
定位结果
├─ 解剖分区   右肺中野（患者右侧）
├─ 侧别映射   图像左侧 · pa_chest: image_left = patient_right
├─ 定位依据   胸片六分区（PA）· 人工标注 · 2026-11-15
├─ 覆盖度     框内 100% · 该区被框住 44%
├─ 边界提示   与「右肺下野」重叠 21%，需精确请缩小范围
├─ 可对照征象 实变 · 空气支气管征 · 肺不张
└─ 该分区结论 双引用 2 · 单引用 1 · 拦截 0
```

每一行都带出处；「定位依据」必须写「人工标注」，不得暗示模型识别。

## 4. 功能二：文献溯源双引用（Dual Citation）

### 4.1 定义：一条结论，两条腿

```
                    ┌── 空间锚点：CASE-006 · REG-006-RML · bbox[0.13,0.44,0.31,0.30]
claim「右肺中野见片状实变」 ┤
                    └── 文献锚点：ACR Lung-RADS v2022 · Category 4A · URL · excerpt hash
```

- `spatial` 与 `doc` **都非空且都通过校验** → `dual`
- 缺任一侧 → `single`，明确标注缺哪一侧
- 任一侧校验失败 → `broken`，默认**不渲染**

「双引用」是**受约束的状态**，不是「引用了两个东西」的营销说法。

### 4.2 引用对象 schema

```json
{
  "cite_id": "CIT-0007-D0",
  "kind": "doc",
  "anchor": {
    "doc_kind": "guideline",
    "doc_id": "GL-TIRADS-03",
    "doc_title": "ACR TI-RADS",
    "version": "2017",
    "locator": "TR4 · 穿刺与随访",
    "excerpt": "TR4 类结节最大径达到约 1.5 cm 时可考虑穿刺…",
    "excerpt_sha256": "2bcb2996",
    "url": "https://www.acr.org/…",
    "retrieved_at": "2026-11-15"
  }
}
```

要点：

- `bbox` 用**归一化坐标**，与分辨率解耦，换尺寸不用重标
- `excerpt` 存**原文摘录 + hash**，不是模型转述；hash 不一致即判「摘录被改写」
- `doc_kind` 取 `guideline` / `sign` / `group`。三类都是可引用锚点，但界面必须区分「条款」「词条」「影像组」——否则用户会以为每条都有指南背书
- `locator.kind` 支持 `section` / `page` / `paragraph` / `table_row`

### 4.3 四道校验门

| # | 校验 | 失败处理 |
| --- | --- | --- |
| 1 | **存在性**：`cite_id` 唯一且在库中 | 删除该引用 |
| 2 | **锚点完整**：bbox 在图内、locator 与 url 非空、region 存在 | 降级 `single` 并标注缺失项 |
| 3 | **内容一致**：`sha256(excerpt)[:8] == excerpt_sha256` | 判定 `broken`，整条拦截 |
| 4 | **时效**：`version` 为当前版本、`retrieved_at` 在 180 天内 | 标注「文献待复核」，不隐藏但显式提示 |

第 3 道是关键：**引用不是「有个链接」，而是「这段文字确实出自那里且没被改写」**。
v1.1 里这条由后端 `evaluate()` 实算，`CLM-007` 的 `broken` 是算出来的。

### 4.4 三态与降级

| 状态 | 颜色 | 界面 | 允许进入最终回答 |
| --- | --- | --- | --- |
| `dual` | 绿 | 两枚胶囊：`影像 右肺中野` / `条款 TR4` | 是 |
| `single` | 琥珀 | 一枚胶囊 + `无空间锚点`（删除线） | 是，但必须显示降级标记 |
| `broken` | 红 | 该句折叠 + 「引用未通过校验」+ expected/actual | 否 |

**故意保留失败案例**：`CLM-007` 把 TI-RADS 的 1.5 cm 改写成 1.0 cm，校验器比对 hash 后拦截。
`CLM-004` 只有文献锚点、没有空间锚点，降级为 `single`。两条都在审计表里可见。

### 4.5 三种阅读方式

| 方式 | 操作 | 用途 |
| --- | --- | --- |
| 胶囊跳转 | 点 `影像` → 图上高亮 bbox；点 `条款` → 右侧抽屉显示原文 | 日常核对 |
| 并排核验 | 开启后点结论，同时高亮影像 + 打开文献 | 答辩「一屏证明」 |
| 引用审计 | 审计面板列出全部 7 条的两侧锚点、hash、失败原因 | 证明门禁真的在跑 |

## 5. 两个功能怎么咬合

```
用户拖框
   │
   ├─► ① 几何匹配 → single / cross / uncovered / too_small / too_large / no_atlas
   │        └─ 侧别映射（图像左 → 患者右）
   │
   ├─► ② 分区 → 征象候选（sign_ids）→ 条款候选（guideline_ids）
   │        └─ 复用 dual.py 的对齐逻辑
   │
   ├─► ③ 取该分区的 claim（claim 由「分区 + 条款」预绑定）
   │
   └─► ④ 引用门禁 → dual / single / broken → 渲染或隐藏
            └─ 审计统计：双引用 5 · 单引用 1 · 拦截 1
```

关键约束：**claim 由「分区 + 条款」共同决定，不由模型自由生成**。模型只负责措辞，不负责决定引用哪一条。这样同样的框永远得到同一组 claim。

  "text": "右肺中野见片状密度增高影，边界不清，其内可见支气管充气征。",
  "sign_ids": ["SIGN-002", "SIGN-014"],
  "guideline_ids": [],
  "disclaimer": "仅作表现对照，不构成诊断意见。",
  "cites": [
    { "cite_id": "CIT-0002-S", "kind": "spatial", "anchor": { "...": "..." } },
    { "cite_id": "CIT-0002-D0", "kind": "doc", "anchor": { "...": "..." } }
  ],
  "note": "文献锚点为征象词条定义（非指南条款）：库内无「实变」为适用条件的条款，故不套用 Lung-RADS。"

## 7. 独立界面设计（v1.1）

### 7.1 设计目标

不是一个「演示页」，而是一个**可以连续处理病例的工作台**。三条约束：

1. **空间优先**：影像占据最大面积，面板不抢图
2. **状态可见**：定位状态、引用状态、门禁统计始终可见，不藏在弹窗里
3. **失败可见**：未覆盖、跨区、拦截都要明确显示，不静默跳过

### 7.2 信息架构

```
┌───────────────────────────────────────────────────────────────────┐
│ 顶栏 54px                                                          │
│ 品牌+v1.1 │ 搜索 │ 全局门禁 5/1/1 │ 并排核验 │ 帮助                │
├──────────┬────────────────────────────────────┬───────────────────┤
│ 病例队列  │  影像工作区                         │  右栏 424px        │
│ 286px    │                                    │ ┌───────────────┐ │
│          │  标题 + 模态/部位/标注状态           │ │ 定位 证据 审计 │ │
│ 全部     │  ┌──────────────────────────────┐  │ ├───────────────┤ │
│ 可定位   │  │                              │  │ │               │ │
│ 待标注   │  │  影像 + 分区叠加 + 框选        │  │ │  面板内容      │ │
│          │  │                              │  │ │               │ │
│ 32 条    │  └──────────────────────────────┘  │ │               │ │
│ 病例卡   │  工具栏：缩放 适应 分区 清除 提示   │ │               │ │
│          │  底栏：来源 / 许可 / bbox           │ └───────────────┘ │
└──────────┴────────────────────────────────────┴───────────────────┘
```

**为什么是三栏而不是两栏**：病例队列是「工作台」与「演示页」的分水岭。有队列，用户是在连续处理病例；没有队列，就只是看一张图。

### 7.3 病例队列

| 元素 | 说明 |
| --- | --- |
| 缩略图 42px | `loading="lazy"`，32 张不全量加载 |
| 编号 + 标题 | 标题单行省略 |
| 模态 / 部位 chip | 来自 `cases.jsonl` |
| 状态 | 绿色圆点 = 已标注；灰色 = 待标注；另有「N 区」绿色 chip |
| 筛选 | 全部 32 / 可定位 3 / 待标注 29 |
| 搜索 | 编号、标题、模态、部位四字段匹配 |

选中态：左侧 2px 青色竖条 + 深青底。待标注病例仍可浏览影像与来源，但**框选被禁用**并提示原因。

### 7.4 影像查看器

| 能力 | 实现 | 说明 |
| --- | --- | --- |
| 框选 | 拖拽矩形 | 归一化坐标，缩放/平移后仍准确 |
| 点定位 | 单击 | 取点所在**最小**分区 |
| 悬停 | 分区名预览 | 不触发请求 |
| 缩放 | 滚轮 / ± / 按钮 | 0.5×—5×，以容器中心为原点 |
| 平移 | Shift+拖动 / 中键 | 与框选互斥，避免误操作 |
| 分区叠加 | G 键或工具栏 | 虚线框 + 左上角分区名 |
| 适应/重置 | F / R | 回到 100% 且居中 |
| 坐标显示 | 底栏 | 实时 bbox，便于核对 |

缩放用 `transform: translate() scale()` 作用在 frame 上，overlay 在 frame 内，因此**百分比坐标天然不受缩放影响**——这是选择百分比而非像素坐标的直接收益。

### 7.5 右栏三面板

| 面板 | 内容 | 设计意图 |
| --- | --- | --- |
| **定位** | 定位卡（分区/侧别/依据/覆盖度/边界提示/征象）+ 直接选择分区 + 本次会话定位记录 | 回答「这是哪儿」 |
| **证据** | 门禁统计条 + 该分区 claim 列表 + 双引用胶囊 | 回答「凭什么」 |
| **审计** | 全部 7 条引用的两侧锚点、hash、状态、失败原因 | 回答「门禁真的在跑吗」 |

审计面板是 v1.1 新增，也是最能说服评委的一屏：**它把「拦截」从文案变成了可核对的数据**（expected 2bcb2996 / actual 0c789cc9）。

### 7.6 状态机

```
未选病例
  └─选择病例─► 无 atlas ──► 仅浏览（框选禁用）
                  │
                  └─有 atlas─► 待框选
                                 ├─拖框─► single ──► 展示定位卡 + 证据
                                 │        cross ──► 并列候选，不展示条目
                                 │        uncovered / too_small / too_large ──► 明确提示
                                 └─点选─► point ──► 展示定位卡 + 证据
```

**跨区与未覆盖都不展示 claim**。这是刻意的：一旦在不确定的位置展示确定的知识，前面所有的严格都白做了。

### 7.7 空态与错误态

| 场景 | 界面 |
| --- | --- |
| 服务未启动 | 队列区显示启动命令，toast 提示「请通过本地服务打开」 |
| 未选病例 | 影像区居中引导，右栏「未选择病例」 |
| 病例无 atlas | 标题 chip「待标注」，右上「未标注分区」，右栏说明「未标注即不推断」 |
| 无匹配病例 | 队列区「没有匹配的病例」 |
| 分区无 claim | 「该分区暂无可对照条目，库内未绑定征象或条款，不作推断」 |
| 引用拦截 | 卡片虚线 + 红色说明 + expected/actual |

## 8. 接口契约（v1.1 已实现）

### 8.1 六个接口

```
GET  /api/meta
     → { version, counts{cases,locatable_cases,atlases,regions,claims},
         gate{dual,single,broken}, thresholds{...} }

GET  /api/cases?filter=all|locatable|pending&q=
     → { items:[{id,title,modality,body_part,image,has_atlas,region_count,claim_count,…}], total }

GET  /api/cases/{id}
     → { case, atlas, regions[], claims[](含 status/gate), gate }

POST /api/locate   { image_id, bbox:[x,y,w,h] }
     → single:  { status, bbox, primary{region,coverage,purity,atlas,signs,claims}, secondary, mode }
     → cross:   { status, bbox, candidates[2], gap }
     → 其他:    { status, message, bbox }

GET  /api/audit
     → { items:[{claim_id,image_id,region_id,text,status,spatial_anchor,doc_anchor,doc_hash,problems[]}], gate }

GET  /images/{name}
```

### 8.2 响应约定

- 几何值归一化，保留 4 位小数
- `status` 六值固定：`single / cross / uncovered / too_small / too_large / no_atlas`，前端不解析文案判断状态
- `gate` 由后端算，前端只渲染，避免两边口径不一致
- 错误统一 `{error, detail}`，400/403/404/500

### 8.3 合规检查待接入项

| 检查 | 规则 |
| --- | --- |
| 分区标注来源 | 每个 region 必须有 `annotator` 与 `annotated_at` |
| 越界词 | claim 文本禁止「诊断」「确诊」「建议手术」「恶性」 |
| 双引用完整性 | 每条 claim 至少 1 个 `spatial` + 1 个 `doc`，否则必须为 `single` |
| 侧别一致性 | `patient_side` 必须与 `laterality_rule` 推导结果一致 |

## 10. 风险与回退

| 风险 | 触发信号 | 回退 |
| --- | --- | --- |
| 分区标注主观、两人不一致 | 同图两次标注 IoU < 0.7 | 双人标注 + 分歧记录；界面标「人工标注」 |
| 左右侧映射错 | 侧别用例失败 | 独立字段 + 单测 + 界面双语标注 |
| 超声/钼靶硬给解剖分区 | 用户质疑「你怎么知道是左叶」 | 降级 `local`，只给图像内相对位置 |
| 多层面/多图拼接 | `CASE-030` 双层面 | 引入 `frame_id`，每层面独立 atlas |
| 网页改版导致 URL 失效 | 核验返回 404 | 存 `excerpt` + hash + 抓取时间；失效降级为「快照可查」 |
| 被误读为 AI 诊断 | 评委追问「这是不是自动诊断」 | 文案禁用「检出/诊断」；固定声明；答辩口径统一 |
| **服务未启动导致空白页**（v1.1 新增） | 直接双击 `index.html` | 队列区显示启动命令 + toast 提示；文档明确入口 |
| **前后端状态不一致**（v1.1 新增） | 前端本地算一套、后端算另一套 | 定位与门禁全部走后端；前端只做点选与渲染 |
| 时间不足 | 11/22 未达标 | 砍多图支持，保「胸片 atlas + 双引用门禁」 |
