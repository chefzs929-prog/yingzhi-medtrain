# 引入 AI 审核：可行性、边界与落地声明

> 版本：v1.0 ｜ 日期：2026-11-18 ｜ 承接 [库容量扩张_痛点与可行性评估](库容量扩张_痛点与可行性评估.md)
> 一句话结论：**AI 审核能把人工从"逐条看"降到"只看高风险 + 签字"，能把审核产能提高约 2.5–3 倍；但它不能替代签字，也不能替代临床判断。**

---

## 0. 结论摘要

| 问题 | 结论 |
| --- | --- |
| AI 能不能做审核 | **能，但只能做"预审"**：格式、引用、一致性、同质化、条款匹配 |
| AI 能不能替代人工 | **不能**：签字是责任主体，AI 没有主体资格；临床正确性必须人看 |
| 能省多少人力 | 10 分钟/例 → **3–4 分钟/例**，审核产能约 **2.5–3 倍** |
| 最大风险 | **假阴性**（AI 放过错误）+ **共谋**（AI 和人一起错） |
| 正确姿势 | **风险分层**：高风险 100% 人工，低风险 AI 预审 + 抽检 |
| 落地前提 | 界面与文档明确：**AI 预审 ≠ 审核通过；正式落地运用前须经医学人员逐条签字** |

---

## 1. 先分清三种"审核"，不能混为一谈

| 类型 | 审什么 | 谁负责 | AI 能做吗 |
| --- | --- | --- | --- |
| **内容审核** | 解剖范围、征象关联、结论表述是否符合医学常识 | 医学审核人 | 只能"提示疑点"，不能"判定正确" |
| **引用审核** | 摘录是否原文、页码/段落是否对、版本是否一致 | 机器 + 人 | **能，且应该 100% 机器做** |
| **放行审核** | 这条内容能不能进正式库、能不能用于教学 | 机构/审核人签字 | **不能**，AI 无签字资格 |

**关键区分**：现在讨论的"AI 审核"，90% 的价值在第二类（引用审核）和第一类的"疑点提示"，不在第三类（放行）。

---

## 2. 三层审核架构

```
L0 机器校验（确定性，0 人工，100% 可解释）
   ├─ schema 完整性：必填字段、枚举值、ID 唯一
   ├─ 引用回跳：span 能否在快照中精确匹配、64 位 hash 是否一致
   ├─ 双引用完整：spatial + doc 是否齐全
   ├─ 侧别/单位/阈值：规则可判定的硬冲突
   └─ 同质化：文本 embedding 聚类，簇内 > 3 条即标记
        │
        ▼
L1 AI 预审（概率性，低成本，只给"建议"）
   ├─ 文本内部一致性：结论是否自相矛盾、是否超出该分区范围
   ├─ 指南条款匹配：结论是否落在所引条款的适用条件内
   ├─ 表述规范：是否出现诊断性措辞（"确诊""恶性""建议手术"）
   ├─ 缺失项提示：该写的侧别/尺寸/程度是否缺失
   └─ 输出：pass / flag / reject / needs_human + 理由 + 证据片段
        │
        ▼
L2 人工终审（责任性，不可替代）
   ├─ 高风险条目 100% 看
   ├─ AI flag/reject 条目逐条裁决
   ├─ AI pass 条目抽检 10%
   └─ 签字：审核人、时间、版本、结论
```

### 为什么 L0 要放在 AI 前面

L0 是确定性的：hash 对不上就是不对，span 匹配不上就是匹配不上。**先把机器能判的判掉，AI 只看剩下的**，既省钱又减少 AI 的"发挥空间"。

上一轮实测：现有 582 条全是 8 位截断 hash、无 span——**L0 一上线就会拦下全部 582 条**。这不是坏事，它说明"引用审核"这一层现在等于没做。

## 3. AI 能审什么、不能审什么

| 能力 | 能做 | 不能做 | 原因 |
| --- | --- | --- | --- |
| 引用核验 | ✅ 摘录是否原文、页码段落是否对 | ❌ 判断文献结论是否可靠 | 后者是证据评价，不是文本比对 |
| 一致性 | ✅ 文本内部矛盾、超范围表述 | ❌ 判断"影像上到底有没有这个征象" | 需要看图做临床判读 |
| 指南匹配 | ✅ 结论是否落在条款适用条件内 | ❌ 替用户选"该用哪版指南" | 版本选择是临床决策 |
| 同质化 | ✅ 聚类、查重、模板句识别 | ❌ 判断"这条是否值得写" | 价值判断 |
| 语言规范 | ✅ 诊断性措辞、绝对化表述 | ❌ 改写医学结论 | 改写会引入新错误 |
| 影像判读 | ❌ **不做** | — | 多模态判读不可靠，且越界为诊断 |

**一条硬边界**：**AI 审核不看图。** 它只审"文本 ↔ 元数据 ↔ 文献"三者的一致性。一旦让 AI 看影像说"这个区域有结节"，产品就从"教学对照"变成"辅助诊断"。

## 4. 人力与成本测算

### 4.1 现状 vs AI 预审后

| 环节 | 现状 | AI 预审后 |
| --- | --- | --- |
| 格式/引用校验 | 人工顺手看 | L0 自动，0 人工 |
| 同质化检查 | 基本没做 | L0 自动聚类 |
| 内容疑点 | 人工逐条读 | L1 标记 20–30%，人工只看这些 |
| 终审签字 | 10 分钟/例 | **3–4 分钟/例** |
| 1000 例审核工时 | 167 人时 | **50–67 人时** |
| 年产能（1 人半工时） | 3000–4000 例 | **8000–10000 例** |

### 4.2 AI 预审成本

| 项 | 估算 |
| --- | --- |
| 单条上下文 | 约 1.5–2k token（结论 + 分区 + 指南条款 + 规则） |
| 1000 例 × 5 条 | 5000 次调用 ≈ 1000 万 token |
| 成本 | 国产模型约 **¥10–50**，可忽略 |
| 延迟 | 批量离线跑，不占用户请求 |

**结论**：AI 预审的成本不是问题，**问题是怎么证明它没放过错**。

## 5. 四种失败模式与对策

| 失败模式 | 表现 | 后果 | 对策 |
| --- | --- | --- | --- |
| **假阴性** | AI 判 pass，实际有错 | 错误流入库 | 高风险 100% 人工；pass 样本抽检 10%；度量假阴性率 |
| **共谋** | AI 和标注人都漏了同一个错 | 系统性错误 | 引入"红队抽检"：不看 AI 结论，独立复核 |
| **漂移** | 模型升级/prompt 改动后标准变了 | 同一条目前后结论不一致 | 审核记录带模型版本 + prompt 版本；固定回归集 |
| **不可解释** | AI 说"不合格"但说不出为什么 | 人工无法裁决 | 强制输出 `reason + evidence_span`，无证据即 `needs_human` |

### 风险分层（决定谁审）

| 条目类型 | 风险 | 审核方式 |
| --- | --- | --- |
| 指南阈值/分类（如 6 mm、Lung-RADS 2） | **高** | 100% 人工 + 双人复核 |
| 侧别/部位/单位 | **高** | L0 规则 100% + 人工抽检 30% |
| 征象-分区关联 | 中 | L1 预审 + 人工 20% |
| 解剖范围描述 | 低 | L1 预审 + 抽检 5% |
| 语言/格式 | 低 | L0 机器 100% |

**一句话**：AI 审"量"，人审"险"。

---

## 6. AI 审核的质量指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 拦截率 | AI 标记的问题条目 / 人工确认的问题条目 | ≥ 85% |
| 误拦率 | AI 标记但人工判合格的 / AI 标记总数 | ≤ 15% |
| **假阴性率** | AI 判 pass 但人工抽检发现错的 / 抽检 pass 数 | **≤ 2%** |
| 抽检一致率 | 人工复核与 AI 结论一致的比例 | ≥ 90% |
| 可解释率 | 带 `reason + evidence_span` 的结论占比 | 100% |
| 回归稳定性 | 固定 200 条回归集上结论变化率 | ≤ 3% |

**假阴性率是最重要的指标**，因为它决定"AI 放过的错"有多少。它只能靠人工抽检度量，不能靠 AI 自评。

## 7. 落地声明（可直接用）

用户要求："后续说明软件的落地运用有待人工审核。"以下三层文案可直接落到产品与文档。

### 7.1 界面 · 每条回答底部（短版）

> 仅作影像表现与文献条款对照，不构成诊断意见，不替代临床决策。内容由文献资料 + AI 辅助整理，**未经医学专家逐例复核**；正式教学使用前须经医学人员审核。

### 7.2 界面 · 问答页合规声明（长版）

> **非诊断用途声明**
> 本应用仅用于医学影像教学与研究，不构成诊断意见，不替代临床决策。病例影像仅使用公开许可来源。
> **分区来源**：分区框是教学用的解剖区域示意，范围按公开胸片解剖分区规范与文献描述确定，由 AI 辅助整理；**开发者不具备医学专业资质，未对影像做人工标注**，分区框不是病灶分割。
> **审核状态**：逐区文本与题目解析由文献资料 + AI 辅助整理，**截至当前版本尚未经影像科医师逐例复核签字**；专家复核已列入未来优化方向，页面提供「反馈」入口收集异议。
> **落地要求**：**正式落地运用前须经具备资质的医学人员逐条审核签字**；未签字条目标注"待审核"，不作为教学依据。

### 7.3 知识库条目字段（数据层）

```json
{
  "audit": {
    "rule_check": "pass",
    "ai_review": {"status": "pass", "model": "xxx", "prompt_version": "v1", "at": "2026-11-18"},
    "human_review": {"status": "pending", "reviewer": null, "at": null, "signature": null}
  }
}
```

界面显示规则：

| `human_review.status` | 显示 |
| --- | --- |
| `approved` | 医学审核：{reviewer}（{date}） |
| `pending` | **待医学审核** · 内容仅供教学参考 |
| `rejected` | 不展示 |

### 7.4 答辩口径（30 秒）

> 我们用 AI 做**预审**，不是做**终审**。AI 负责三件确定性的事：引用能不能回跳、结论有没有自相矛盾、内容是不是模板复制。这三件它比人快，也比人稳。
>
> 但"这条结论在医学上对不对、能不能用于教学"，必须由有资质的人签字。所以我们的流程是 **规则校验 → AI 预审 → 医学终审签字**，未签字的条目在界面上明确标"待审核"。
>
> **软件当前处于教学演示阶段，正式落地运用有待人工审核。** 这不是免责话术，是流程的一部分：AI 把 80% 的机械检查做掉，人只对 20% 的高风险项负责。
>
> 还要主动说明一点：**开发者不具备医学专业资质，影像分区不是开发者人工画的**。分区的范围来自公开解剖分区规范与文献描述，逐区文本由 AI 辅助整理与一致性核查。所以"专家复核"不是可选项，而是这个产品能否走出演示阶段的前提——我们把这件事写进了未来优化方向，也在页面上开了反馈入口，让医师的异议能直接落到具体病例和分区上。

## 8. 合规边界：教学 vs 诊断

| 定位 | 能不能说 | 后果 |
| --- | --- | --- |
| 教学/研究工具 | ✅ 能 | 不进入医疗器械监管 |
| 辅助诊断软件 | ❌ 不能说 | 可能构成 SaMD，需注册 |
| "AI 审核后可用于临床" | ❌ **绝对不能说** | 把责任转移给 AI，且越界 |

**三条措辞红线**：

1. 不说"AI 审核通过" → 只说"AI 预审通过，待医学审核"
2. 不说"可用于临床" → 只说"用于教学与研究"
3. 不说"替代医师判断" → 只说"不替代临床决策"

## 9. 分阶段落地

### 阶段 0（黑客松内，1 天）

- L0 机器校验脚本：schema + span 回跳 + 64 位 hash + 双引用 + 同质化聚类
- 跑全量 582 条，输出"待修清单"
- 界面补 7.1 / 7.2 声明
- 答辩口径定稿

### 阶段 1（1 个月）

- L1 AI 预审上线：只做"引用一致性 + 诊断性措辞 + 同质化"
- 建 200 条回归集，测假阴性率
- 风险分层规则落地
- 审核记录字段上线（`audit`）

### 阶段 2（3 个月）

- 人工终审流程 + 签字
- 抽检机制 + 红队复核
- 审核看板：拦截率、误拦率、假阴性率、待审数
- 与内容生产流水线打通（路径 C）

## 10. 结论

**AI 审核值得引入，但要把它放在正确的位置：**

- 它解决的是**"量"**：格式、引用、同质化、措辞——这些机器比人快、比人稳
- 它解决不了**"责"**：医学正确性、教学适用性、放行签字——这些必须人做
- 它最大的风险不是"审错"，是**"让人以为已经审过了"**

所以正确的产品表达不是"AI 审核通过"，而是：

> **规则校验 → AI 预审 → 医学终审签字**；未签字的条目明确标注"待审核"；**软件正式落地运用有待人工审核**。

这句话既是对用户的诚实，也是对产品的保护。
