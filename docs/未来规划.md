## P1 · 容器化部署（直连模型）

**触发条件**：需要 7×24 在线、多人同时使用，或演示不再依赖个人电脑。

**现状**：推理层已具备。`llm.py` 的直连分支实测可跑（纯文本 6.9s / 带图 15.4s / 合规拦截 0ms），
凭据有效。缺的是服务外壳与 4 处契约修复。

**必须先改的 4 项**（详见 [Agent云端部署_实测可行性_2026-11-23.md](Agent云端部署_实测可行性_2026-11-23.md) 第 4 节）：

1. 监听地址写死 `127.0.0.1`（[main.py:1790](../yingzhi/serve/main.py#L1790)）→ 加 `--host`，容器传 `0.0.0.0`。
2. `ok` 只看 gateway、`real_llm` 不含直连模型、`inference_location` 硬编码 → 三处口径按实际来源计算。
3. 前端读 `llm_route.ready`，后端不返回该字段 → 统一契约。
4. 无鉴权、无限流、CORS `*` → 加 `YZ_API_TOKEN` + 按 IP 限流 + Origin 白名单。

**工作量**：0.5 人日到「能对外」。
**口径变化**：`served_by` 从 `agent` 变成 `llm`，必须在页面与口播中主动说明，不能冒充 Agent。

**不做的事**：不把 DeepWorks 桌面引擎容器化（依赖本机进程发现与进程环境凭据，无 Linux 服务端形态）。

## P2 · 双引用补齐（公网开放前必须）

**触发条件**：任何对外公开的问答入口。

**现状实测**：

| 场景 | 影像锚点 | 文献锚点 |
| --- | --- | --- |
| 纯文本 | 1 | 0 |
| 带图 | 0 | 0 |

验收要求是「1 个影像锚点 + 1 个文献锚点」，当前不达标。带图 0 引用最严重：`vision_percept`
拿到了 findings，却没有映射回 `sign_ids`，等于「看图说话」，落不到证据。

**方向**（不放宽既有约束）：

- 带图：`percept.sign_terms` 与 `Retriever` 的征象名/别名匹配，命中即发 `citation`。
- 文本：`claims` 已有 `source_url`，按 `sign_ids` 取最高 `evidence_level` 的一条作文献锚点，标 `match=candidate`。

**工作量**：0.5–1 人日。

## P3 · 视觉 bbox 能力验证

**触发条件**：要在云端提供「区域定位」。

**现状**：`VISION_SCHEMA` 声明了 `bbox`，实测只回 `modality/view/findings`，未回 bbox。
若模型确实不产 bbox，「区域定位」在云端落不了地。

**动作**：用 5 张不同病种的胸片验证；确认不产 bbox 则换视觉模型，或降级为「模板分区 + 文字定位」。
**不要**在未验证前对外宣称支持框选。

## P4 · 静态站与 API 分离

**触发条件**：访问量上来，或需要独立更新内容而不重启服务。

**方向**：站点（10 MB / 102 文件）进对象存储或 CDN；容器只跑 `/api`。
注意跨域与混合内容，届时 CORS 白名单必须收紧。

## 明确不做

| 项 | 原因 |
| --- | --- |
| Serverless（Lambda / Vercel Functions） | 带图请求实测 15.4s，叠冷启动易撞超时；SSE 支持参差；低访问量下收益抵不过调试成本 |
| 把 DeepWorks 引擎打包进容器 | 依赖本机进程发现与进程环境凭据，没有 Linux 服务端形态 |
| 为检索引入向量库 | `signs` 60 / `concepts` 136 / `claims` 434 条，内存全量载入足够 |
| 前端存放模型 key | 前端只能拿到后端地址，key 只留在服务端环境变量 |
| 用隧道冒充「正式部署」 | 隧道依赖个人电脑在线，域名每次变化，只能用于演示 |
