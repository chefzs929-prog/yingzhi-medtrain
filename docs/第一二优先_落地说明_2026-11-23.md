## 1. 第一优先：把创新变成可验证证据

### 1.1 引用一致性审计

**脚本**：`kb/scripts/attach_sign_cites.py`（补词条锚点，幂等）+ `kb/scripts/audit_citations.py`
**报告**：[引用一致性审计_2026-11-23.md](引用一致性审计_2026-11-23.md)
**原始结果**：`outputs/medtrain/data/audit/citation_audit.json`

检查项：

- 病例 / 分区是否存在；
- spatial cite 的 bbox 是否合法、是否落在分区框内；
- doc cite 的 `doc_id` 是否可解析；
- excerpt 的 sha256 是否与记录一致、`hash_ok` 是否诚实；
- `dual_status` 是否与 cites 组合一致；
- `audit.rule_check` 是否与本次检查一致。

结果：

| 口径 | claims | 通过 | 失败 | 有征象 | 指南级 dual | 词条级锚点 | 二级锚点覆盖 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 全库 | 434 | 433 | 1 | 101 | 9 | 78 | 85/101（84.2%） |
| 胸片发布集 | 99 | 99 | 0 | 35 | 4 | 26 | 28/35（80.0%） |

另有 333 条（发布集 64 条）无征象的正常对照/解剖标注，本身不存在第二锚点，不纳入分母。

**必须修正的话术**：不能说“每条答案都同时带 E1+L1”。准确说法：

> 有征象的 claims 已基本做到“影像分区锚点 + 第二锚点”：9 条挂指南/文献条款，78 条挂库内征象条目定义；正常对照与解剖标注保持影像单锚点。指南级双引用仍是 9/434，不能表述为“全库每条都双引用”。

唯一失败是 `CLM-011-BROKEN`，故意构造的 hash 不一致演示样本，不计入胸片发布集。

### 1.2 第四态抽检 + SOP

**脚本**：`kb/scripts/build_review_queue.py`
**SOP**：[第四态抽检_SOP.md](第四态抽检_SOP.md)

- 全库 `unmentioned` 58 条；按病例分层抽 20 条，固定随机种子 `20261123`。
- 关键定义：**“未提及”指来源没有逐区描述，不等于“来源完全没提”，也不等于“正常”。**
- AI-A 报告视角：只读病例级公开描述，判断是否覆盖该分区；先看层级词（上/中/下），再看“双肺/双侧”，避免“双肺上野”错误覆盖中下野。
- AI-B 结构化视角：只读 `sign_ids / zone.status / claim.text`。

### 1.3 双 AI 预标注 + 专家复核入口

**报告**：[双AI预标注报告_2026-11-23.md](双AI预标注报告_2026-11-23.md)
**页面**：`outputs/medtrain/read/qc.html`（课堂页头部“质控复核”）

| 指标 | 结果 |
| --- | --- |
| 双 AI 标注 | 30 条（abnormal / normal / unmentioned 各 10） |
| 一致 | 24/30（80%） |
| Cohen's kappa | 0.5263 |
| 第四态抽检一致 | 11/20（55%） |
| 第四态 kappa | -0.0976 |
| 冲突总数 | 15 条 |
| claim 缺失 | 18 条 |
| 状态与文本冲突 | 8 条 |
| 状态与征象冲突 | 14 条 |

**怎么读**：

- 双 AI 80% 一致、kappa 0.53，属于中等一致；说明两个视角可互相筛冲突，但不能互相替代。
- 第四态 kappa 为负，是**系统性分歧**：报告视角认为病例级描述覆盖了该区，结构化视角认为 claim 明确写“未逐区”。这不是“AI 很准/很烂”，而是**数据粒度冲突**，必须专家裁决。
- 18 条 claim 缺失、8 条状态-文本冲突、14 条状态-征象冲突，是比 kappa 更值得修的数据质量问题。

**专家入口**：

- 每条显示来源描述、claim 文本、AI-A/AI-B 判定与理由；
- 专家选择“来源未逐区提及 / 已提及异常 / 已提及正常 / 支持当前状态 / 不支持 / 存疑”，填备注；
- 保存到 `localStorage`，可导出 JSON 归档；
- 页面明确写“AI 预标注不是金标准”。

## 2. 第二优先：教学闭环纵深

### 2.1 课堂可选服务端同步

**服务端**：`kb/server/classroom_server.py`（Python 标准库 + SQLite，无第三方依赖）
**前端**：`kb/app/classroom-sync.js`
**验收**：`outputs/medtrain/classroom_sync_check.md`（10/10）

启动：

```bash
python3 kb/server/classroom_server.py --port 8820
# 课堂页点“同步设置”，或：
# read/classroom.html?sync=http://127.0.0.1:8820
```

能力：

- `GET /api/health`、`GET /api/snapshot`、`POST /api/merge`、`POST /api/reset`；
- 按 code / name / id 合并，学生、作业、答题、帖子、回复都不丢；
- 前端写操作 900ms 防抖推送；页面回到前台自动拉取；
- 服务不可达自动回退“本机模式”，不白屏、不报错；
- 头部状态：本机模式 / 同步中 / 已同步 / 离线。

**边界**：单库快照、无鉴权、无并发数据库；只用于本机/内网演示，不要暴露公网。

### 2.2 教师备课包

**入口**：教师端「作业编排」或「班级概览」的作业卡片 →「备课包」
**验收**：`outputs/medtrain/lesson_pack_check.md`（10/10）

导出 Markdown，包含：

- 班级、截止、及格线、病例数；
- 每例的体位/质量、教学提示；
- 分区表（分区 / 状态 / 来源文本 / 依据）；
- 征象与定义；
- E1（病例/分区/bbox）与 L1（来源标题/链接）；
- 题目与答案（定位 / 判读 / 征象）；
- 讲评提示（先指框、未提及不等于正常、正常对照练“不虚构异常”）。

### 2.3 错题归因 + 7 天计划

**入口**：学生端「我的作业」→ 7 天练习计划
**验收**：`outputs/medtrain/student_plan_check.md`（8/8）

- 归因：定位错误 / 判读错误 / 征象不全 / 综合；
- 错题按病例去重，取最低分，按 7 天分配，每天 1–2 例；
- 每条可直接跳回 `clinic.html` 重练；
- 无错题时显示“暂无计划”，不硬凑。

### 2.4 能力雷达图

**入口**：学生端「我的作业」→ 能力雷达
**四维**：

- 定位 = 平均 `zonePoints / 40`
- 判读 = 平均 `statusPoints / 30`
- 征象 = 平均 `signRatio`
- 依据 = **错题病例中重练过的比例**（行为代理，不等于“读过出处”）

页面明确写“依据是行为代理”，避免把重练率冒充出处阅读率。没有作答时显示空状态，不画 0 分雷达。

### 2.5 帖子关联分区 / 征象

**验收**：`outputs/medtrain/forum_zone_check.md`（9/9）

- 发帖表单新增“关联分区 / 关联征象”；
- 选择病例后分区下拉动态填充；
- 帖子详情显示分区、征象标签；
- 点击病例卡跳 `clinic.html?case=...&zone=...`，阅片台自动选中该分区。

## 4. 演示建议（7 分钟）

1. **30 秒**：打开质控复核页，先看“50 条 / 15 条 AI 冲突”，说明 AI 只筛冲突。
2. **90 秒**：点一条第四态冲突，展示“来源描述 vs claim 文本 vs AI-A/AI-B”，选专家结论并保存，导出 JSON。
3. **60 秒**：打开学生端，展示能力雷达与 7 天计划，点一条重练。
4. **90 秒**：教师端导出备课包，展示分区表、E1/L1、题目与答案。
5. **90 秒**：两个浏览器窗口演示课堂同步：A 建班/提交，B 刷新看到；关掉服务演示离线回退。
6. **60 秒**：互助小组帖子关联分区，点击跳阅片台自动选中。
7. **30 秒**：收尾一句话——“我们不是又做了一个 AI 读片，而是把读片的证据做成了可教、可练、可查的结构。”
