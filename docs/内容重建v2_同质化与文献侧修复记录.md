## 1. 根因：不是"写得多"，是"只用了三个变量"

原 claim 的生成代码只有三个变量（[build_corpus_120.py](kb/scripts/build_corpus_120.py#L414)）：

```python
text = f"{r['name']}区域解剖范围为{r['note']} 库内关联征象包括{names}；本条目只作分区与征象对照，不构成诊断。"
```

而库里其实有更多可用、且**不需要新增医学判断**的字段：

| 字段 | 数量 | 原来是否用上 |
| --- | --- | --- |
| `case.title` | 119/120 唯一 | ❌ |
| `region.note` | 73 种 | ✅（但只拼一句） |
| `sign.appearance` | 60 条 | ❌（只用于文献锚点） |
| `sign.pitfalls` | 60 组 | ❌ |
| `sign.may_see_in` | 60 组 | ❌ |
| `guideline.statement` | 47 条 | ❌（只挂了 4 条） |
| `guideline.conditions` | 47 组 | ❌ |

**结论**：同质化的根因是"字段利用率低"，不是"内容不够"。

---

## 2. 做法：三件事，每条都能追溯

### 2.1 建段落库（解决"文献侧空心"）

把指南和征象切成**段落级**，而不是一句摘要：

| 段落类型 | 来源字段 | 数量 |
| --- | --- | --- |
| 指南条款 | `guideline.statement` | 47 |
| 指南前提 | `guideline.conditions[]` | 106 |
| 征象表现 | `sign.appearance` | 60 |
| 征象鉴别 | `sign.pitfalls[]` | 120 |
| 征象场景 | `sign.may_see_in[]` | 213 |

每段字段：

```json
{
  "para_id": "SIGN-001#appearance-1",
  "doc_id": "SIGN-001",
  "doc_kind": "sign",
  "section": "appearance",
  "para": 1,
  "char_start": 0,
  "char_end": 52,
  "text": "肺野密度轻度增高，但其内血管与支气管边缘仍可辨认……",
  "sha256": "完整 64 位",
  "version": "v2026-11-15",
  "source_url": "kb://sign/SIGN-001",
  "page": null,
  "page_status": "pending_source_pdf"
}
```

**诚实的局限**：`page` 仍为 `null`。源数据（`guidelines.jsonl`）只有官网首页链接，没有原始 PDF 页码。要补页码，必须先有 PDF 快照——这一步没做，也不假装做了。

### 2.2 重建文本（解决"同质化"）

每条 claim 由五段组成，**有则写、无则省**：

1. **本例定位**：`{case.title} · {region.name}：{region.note}`
2. **表现**：`该区对应表现「{sign.name}」——{sign.appearance}`
3. **鉴别**：`鉴别上需注意：{sign.pitfalls}`（无则省）
4. **场景**：`可见于{sign.may_see_in}；本条只作表现对照，不据此判断病因`
5. **条款**：`同部位相关条款（候选，适用性需人工判断）：{standard} {category}——{statement}（{version}）；条款前提：{conditions}`

示例（CLM-0016）：

> 胸片解剖标注（欠吸气、轻度旋转） · 右肺上野：肺尖至第 2 前肋下缘水平。该区对应表现「磨玻璃影」——肺野密度轻度增高，但其内血管与支气管边缘仍可辨认；不掩盖其内血管与支气管轮廓。鉴别上需注意：需与部分实性结节中的实性成分区分；另外，层厚与窗宽会影响显示，薄层更可靠。可见于炎症性渗出、局灶性纤维化、肿瘤性病变或肺水肿或出血；本条只作表现对照，不据此判断病因。同部位相关条款（候选，适用性需人工判断）：Fleischner 偶发肺结节建议 单发磨玻璃 < 6 mm——单发磨玻璃结节 < 6 mm，通常无需常规随访（2017）；条款前提：偶然发现、单发磨玻璃结节、< 6 mm。

**每条内容都可回溯到源字段，没有新增一句医学断言。**

### 2.3 纠错：正常病例不再挂征象

改造前：

| 病例 | 标题 | 被挂的征象 |
| --- | --- | --- |
| CASE-002 | 正常侧位胸片 | 磨玻璃影、实变、结节 |
| CASE-014 | 正常头颅 CT 三视图 | 脑膜强化、占位效应 |

这是模板按体位分配征象、不看病例是否正常导致的。v2 规则：`title` 或 `description_public` 含"正常"→ 不挂征象，只写解剖对照。

共修正 **12 个分区**。

## 3. 指南匹配为什么叫"候选"

自动匹配规则：`部位归一化相同` + `模态有交集` + `征象词/别名与条款关键词有重叠`。

但规则匹配有语义风险。例如：

- 「磨玻璃影」的别名含「磨玻璃结节」→ 命中 Fleischner「单发磨玻璃 < 6 mm」
- 但**磨玻璃影 ≠ 磨玻璃结节**，6 mm 阈值不能直接套用

所以 v2 的处理是：

1. 文本写「同部位相关条款（**候选，适用性需人工判断**）」
2. 锚点 `match` 字段标 `candidate`，不标 `strong`
3. `audit.human_review.status = pending`

**不声称"依据"，只说"相关"**。这比"挂一条看起来很像的条款"更诚实，也更能通过医学审核。

## 4. 兼容性与落地

v2 没有另起炉灶，而是保持旧字段名，避免前端重写：

| 旧字段 | v2 处理 |
| --- | --- |
| `anchor.excerpt` | 写入段落原文 |
| `anchor.locator` | `{category} · {section}`（+ 第 N 段） |
| `anchor.excerpt_sha256` | **升级为 64 位** |
| `anchor.version` / `url` | 保留 |
| `claim.id` | **沿用原 id**（selftest 的 CLM-007 等仍有效） |
| `claim.sign_ids` / `guideline_ids` | 保留 |

两处校验同步升级：

- [build_data.py](medtrain/build_data.py#L68)：`full_hash` 兼容 64 位，8 位旧值仍可校验
- [serve_region.py](kb/scripts/serve_region.py#L52)：同上；并去掉"必须外链 URL"的硬要求（词条没有外链，用 `kb://sign/...` 追溯）

落地命令：

```bash
python3 kb/scripts/rebuild_content_v2.py     # 生成 v2
cp kb/data/v2/claims.jsonl kb/data/claims.jsonl
cp kb/data/v2/paragraphs.jsonl kb/data/paragraphs.jsonl
python3 medtrain/build_data.py               # dual 569 / broken 0
python3 medtrain/build.py                    # 重建页面
```

回滚：

```bash
cp kb/data/claims.v1.jsonl kb/data/claims.jsonl
python3 medtrain/build_data.py && python3 medtrain/build.py
```

## 5. 遗留问题（不掩盖）

| 问题 | 现状 | 影响 | 下一步 |
| --- | --- | --- | --- |
| **结构同质化仍在** | 唯一文本 100%，但同一病例多区仍是同一套五段式 | 读 10 条会发现"句式一样" | 人工为每区选征象/写结论（路径 C） |
| 征象仍是模板分配 | 31/60 被用，多数来自模板而非病例标注 | 个别病例可能挂得牵强（如解剖标注片挂磨玻璃影） | 用 `sign_tags` 或人工校正；`derivation.sign_source` 已标记来源 |
| 指南匹配是"候选" | 53.1% 有候选条款，但未逐条验证适用性 | 不能直接当"依据"用 | 人工复核 309 条，保留/剔除 |
| 页码缺失 | `page: null`，`page_status: pending_source_pdf` | 无法定位到 PDF 第几页 | 补 PDF 快照与页码 |
| 段落库未进 kb.json | 目前只在 `kb/data/paragraphs.jsonl` | 前端还看不到"段落级"展示 | 阶段 1 接入详情面板 |
| 文本变长 | 中位 243 字，kb.js 2.62 MB | 首屏变大、卡片变长 | 列表截断 + 详情展开；400 例前分片 |

## 6. 一句话

**这一轮把"同一条结论复制 27 遍"改成了"每条结论有自己的病例、分区、征象、鉴别和条款"；把"8 位前缀 + 一句摘要"改成了"546 段 + span + 64 位 hash"。**

但它仍是"用真实字段重新组装"，不是"人工逐条判读"。**去重做到了，去模板化还没做到**——后者需要人，不能靠脚本。
