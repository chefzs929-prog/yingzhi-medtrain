## 0. 一页结论

**一个知识底座、四个功能链条、三种角色外壳、两种设备形态、七个可运行入口。**

| 维度 | 方案 |
| --- | --- |
| 知识底座 | 60 条征象、47 条指南条款、120 例公开影像、615 个解剖分区、599 条双引用结论、29 道可练题 |
| 四链条 | 01 基础知识问答 → 02 临床知识迁移 → 03 真实病例演练 → 04 真实场景应用 |
| 三角色 | 学生端、教师端、医生端；同一引擎，只换导航、链条任务与可见模块 |
| 两设备 | 桌面三栏 / 移动单列；同一页面，只换布局、导航形态与交互密度 |
| 七入口 | 通用自适应版 + 学生/教师/医生 × 桌面/移动 |
| 比赛硬约束 | 核心链路在 DeepWorks 内运行；本目录是交互层与离线演示包，不是替代核心的“壳工程” |
| 合规边界 | 公开许可影像、无真实患者数据、不做病灶检测/分割、不输出诊断与治疗建议 |

**一句话创新点：** 把影像教学拆成“可核对的条件”，让每一次问答、迁移、演练和核验都留下空间锚点、文献锚点与运行回执。

## 1. 比赛要求拆解

### 1.1 赛制与评分

| 评分维度 | 权重 | 观察点 | 本方案的对应证据 |
| --- | --- | --- | --- |
| 项目背景 | 30 | 竞品、可行性、创新性 | 现有 PACS 关键词检索、通用问答、题库类产品的能力缺口；双引用与四链条的差异 |
| 实用性 | 30 | 真实任务、流程合理、样例/反馈 | 三类角色的真实任务流、29 道可练题、班级与工作台样例、可导出报告 |
| 迭代记录 | 10 | 赛前基础、真实改进、测试反馈 | v1.1 区域定位 → v2.0 双场景 → v2.1 多版本；每轮改动有可复现验收 |
| 最终成品 | 30 | 演示稳定、核心可复现、材料完整 | 7 个入口、离线可开、Playwright 逐版验收、DeepWorks 导入包与配置说明 |

### 1.2 三条硬约束

1. **核心链路必须在 DeepWorks 内**：知识库接入、技能与工作流编排、Agent 运行，不能以外部框架或自建后端为主体。
2. **决赛现场必须在 DeepWorks 环境内实时演示**：不能只放录屏或静态截图。
3. **赛道 B 合规**：不使用真实患者数据，内置“非诊断用途”声明，素材来源与许可可追溯。

### 1.3 对软件方案的三点直接影响

| 要求 | 设计动作 |
| --- | --- |
| 不能是壳工程 | 把“检索 → 双线对齐 → 判分 → 引用审计”定义为 DeepWorks 技能；界面只消费结果，并在每条回答上显示运行回执 |
| 现场要稳定 | 提供离线演示包与本地知识底座；DeepWorks 不可用时仍能完整走通四链条，但明确标注“本地演示态” |
| 多版本不能复制三套代码 | 单引擎 + 角色配置 + 设备布局；所有版本共用同一份数据、同一套判分与审计逻辑 |

## 3. 四个基本功能链条

四链条不是四个孤立页面，而是同一条“从知识到任务”的工作流四段。每一段都要求：**输入明确、处理可解释、输出可核对、失败有边界。**

### 3.1 链条 01 · 基础知识问答

| 项 | 设计 |
| --- | --- |
| 用户问题 | 这个征象是什么？怎么看？容易和什么混淆？依据在哪？ |
| 输入 | 术语、口语描述、部位、模态；例如“磨玻璃影”“甲状腺低回声结节” |
| DeepWorks 处理 | 知识库检索（BM25 + 2-gram + 同义词）→ 征象技能抽取 → 双线对齐技能 → Agent 汇总 |
| 输出 | 定义、可见于、易错点、模态/部位、相关病例、对照词条、条款条件、出处 |
| 证据 | 每条词条带 `source_refs`；每条条款带适用条件；没有依据时明确显示“库内暂无足够依据” |
| 失败边界 | 检索不到不猜测；条款只作原文摘录，不转述为建议；不输出诊断 |

**三角色差异**

| 角色 | 任务说法 | 关键动作 |
| --- | --- | --- |
| 学生 | 学 · 基础知识问答 | 逐条学习、收藏、看易错点、跳到迁移或病例 |
| 教师 | 学 · 知识备课 | 按部位/模态/条款条件备课，选对照词条做课堂素材 |
| 医生 | 学 · 知识速查 | 读片前 30 秒查定义、易错点、条款条件与可对照病例 |

### 3.2 链条 02 · 临床知识迁移

| 项 | 设计 |
| --- | --- |
| 用户问题 | 换模态、换部位、换病种，同一个征象还成不成立？ |
| 输入 | 一个征象 + 目标维度（CT/CR/MR/US/MG、部位、病种） |
| DeepWorks 处理 | 近邻词条检索 → 同标签跨部位检索 → 条款条件核对 → 迁移卡生成 |
| 输出 | 迁移坐标矩阵、迁移三问、对照表、条款条件清单、可落地病例、可导出迁移卡 |
| 证据 | 近邻关系、同标签共现、条款条件；勾选只代表“已完成核对”，不代表个体满足条件 |
| 失败边界 | 没有近邻就显示“库内暂无”；不按概率排序“可见于”；不把条款条件转成处置建议 |

**三角色差异**

| 角色 | 任务说法 | 关键动作 |
| --- | --- | --- |
| 学生 | 迁 · 临床知识迁移 | 选词条 → 看三问 → 对照近邻 → 生成迁移卡 |
| 教师 | 迁 · 迁移设计 | 把“换模态/换部位/换病种”设计成可布置的对照任务 |
| 医生 | 迁 · 跨场景鉴别 | 跨模态、跨部位对照，先核对条件与易错点 |

### 3.3 链条 03 · 真实病例演练

| 项 | 设计 |
| --- | --- |
| 用户问题 | 在真实影像上，我能不能先定位、再描述、再认征象、最后找到依据？ |
| 输入 | 公开许可病例 + 教学解剖分区（文献 + AI 辅助整理） + 题库选项 |
| DeepWorks 处理 | 病例工作流：定位 → 描述 → 征象 → 依据；每步 25 分，多选错选扣分；结果写入错题本 |
| 输出 | 四步得分、总分、错因、解析、条款对照、影像许可与来源页、判分运行回执 |
| 证据 | 分区 bbox、claim 双引用、文献摘录、条款条件；框是解剖区，不是病灶分割 |
| 失败边界 | 定位错误给出正确分区；描述/依据错误给出对应项；不展示自动诊断结论 |

**三角色差异**

| 角色 | 任务说法 | 关键动作 |
| --- | --- | --- |
| 学生 | 练 · 真实病例演练 | 随机一例、按部位筛选、四步计分、错题重练 |
| 教师 | 练 · 组卷与课堂演练 | 从题库组卷、预览、课堂投屏、讲评清单 |
| 医生 | 练 · 读片演练 | 四步读片、结果回工作台核验、用于读片会与带教 |

### 3.4 链条 04 · 真实场景应用

| 角色 | 场景 | 输入 | 输出 | 证据 |
| --- | --- | --- | --- | --- |
| 学生 | 实习任务 | 已布置任务、演练记录、错题 | 任务进度、能力画像、错题本、可导出学习报告 | 本地 `progress`、任务病例、四链条完成度 |
| 教师 | 班级教学 | 班级演示数据、作业、错题 | 班级概览、作业编排、错题分析、课堂投屏、班级报告 | 32 人演示班级、错题聚合、作业记录 |
| 医生 | 临床读片 | 120 例病例队列、分区、双引用结论 | 病例工作台、引用审计、核验记录、交班摘要 | 空间锚点 + 文献锚点 + hash 校验 |

**链条 04 的完成口径**

- 学生：已完成任务数 / 总任务数；任务完成按“该任务的病例是否练过”计算。
- 教师：班级应用均分；作业数、错题数、投屏可用性作为辅助指标。
- 医生：已核验结论数 / 12；核验动作显式写入本地记录，不自动判定“已读”。

## 4. 角色 × 设备矩阵

### 4.1 三种角色

| 角色 | 一句话 | 首屏主任务 | 导航差异 | 链条 04 |
| --- | --- | --- | --- | --- |
| 学生 | 把一条知识，练成四种能力 | 今日一例 + 能力画像 | 学 / 迁 / 练 / 用 / 我的 | 实习任务、错题本、学习报告 |
| 教师 | 把一份病例，讲成一条证据链 | 班级概览 + 待讲评 | 学 / 迁 / 练 / 教 / 我的 | 班级、作业、错题、投屏 |
| 医生 | 把一次读片，留下可核对的依据 | 读片入口 + 引用健康度 | 学 / 迁 / 练 / 用 / 我的 | 工作台、审计、核验、交班 |

**角色只改变三件事：** 导航与首屏、四链条的任务说法与完成口径、可见模块与导出物。检索、双线判断、四步判分、引用审计完全共用。

### 4.2 两种设备

| 维度 | 桌面 | 移动 |
| --- | --- | --- |
| 布局 | 左侧栏 + 顶部搜索 + 三栏内容 | 单列卡片 + 底部 5 键 + 顶栏角色下拉 |
| 信息密度 | 高：表格、并排对照、三栏工作台 | 低：一屏一件事，表格横向滚动或卡片化 |
| 导航 | 侧栏分组“四链条 / 工作台” | 底部导航，保留四链条主入口 |
| 影像 | 大画布、分区并排、证据侧栏 | 图片限高、分区触控点选、证据下置 |
| 角色切换 | 顶栏三段开关 | 顶栏下拉，切换后保留移动布局 |
| 演示方式 | 直接投屏 | 桌面 430px 画框预览 / 真机 390px |

### 4.3 七个入口

| 入口 | 文件 | 角色 | 设备 | 说明 |
| --- | --- | --- | --- | --- |
| 通用自适应版 | `app.html` | 可选 | 自动 | 一套布局响应式，适合评委快速看全貌 |
| 学生 · 桌面 | `student.html` | 学生 | 桌面 | 完整学习闭环 |
| 学生 · 移动 | `student-mobile.html` | 学生 | 移动 | 碎片学习、触控演练 |
| 教师 · 桌面 | `teacher.html` | 教师 | 桌面 | 备课、组卷、讲评、投屏 |
| 教师 · 移动 | `teacher-mobile.html` | 教师 | 移动 | 巡课、随时看班 |
| 医生 · 桌面 | `doctor.html` | 医生 | 桌面 | 读片、核验、审计、交班 |
| 医生 · 移动 | `doctor-mobile.html` | 医生 | 移动 | 床旁速查、核验、复制出处 |

> 版本入口只负责写入 `role` / `device` 参数；真正的差异由同一引擎根据参数渲染，避免三套代码漂移。

## 6. 软件架构

### 6.1 分层

```
┌─────────────────────────────────────────────────────────┐
│ DeepWorks 核心（比赛要求的主体）                          │
│  知识库：征象 / 指南条款 / 公开病例 / 解剖分区 / 双引用结论 │
│  技能：征象检索 · 双线对齐 · 四步判分 · 引用审计           │
│  工作流：学 → 迁 → 练 → 用；教师布置 → 学生完成 → 讲评     │
│  Agent：汇总为带出处的描述性回答，守住“不诊断”边界         │
└───────────────────────┬─────────────────────────────────┘
                        │ 只读数据 / 运行结果 / 导出包
┌───────────────────────▼─────────────────────────────────┐
│ 多端交互层（outputs/medtrain）                            │
│  角色外壳：导航、首屏、链条文案、可见模块                  │
│  设备布局：桌面三栏 / 移动单列                              │
│  本地记录：学习、迁移卡、演练、作业、核验                  │
│  运行回执：把每次回答/判分/核验拆成四段可核对链路          │
└─────────────────────────────────────────────────────────┘
```

### 6.2 为什么不是“壳工程”

| 质疑 | 回应 | 证据 |
| --- | --- | --- |
| 只是静态页面？ | 页面消费的是知识库构建产物；检索、双线、判分、审计逻辑在技能层，界面只呈现 | `kb/scripts/`、`data/kb.js`、运行回执 |
| 没有 Agent？ | Agent 负责把多段检索/对齐结果汇总为一句可核对回答，并显式标注缺失条件 | 问答页“本次回答的运行链路” |
| 多端是不是三套？ | 单引擎 + 参数化角色/设备；七个入口共用同一份 JS 与数据 | `medtrain/build.py`、版本矩阵 |
| 现场断网怎么办？ | 提供离线演示包；本地知识底座与 DeepWorks 导入包同源，界面标注“本地演示态” | `outputs/medtrain/README.md` |

### 6.3 数据契约（节选）

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| `signs` | `id`、`name`、`en`、`body_part`、`modality`、`appearance`、`pitfalls`、`may_see_in`、`source_refs` | 基础知识问答、迁移 |
| `guidelines` | `standard_name`、`category`、`statement`、`conditions`、`version` | 双线判断、条款条件 |
| `cases` | `id`、`title`、`image`、`modality`、`body_part`、`license`、`source_page` | 病例演练、工作台 |
| `regions` | `id`、`image_id`、`name`、`coords`、`derivation` | 定位、分区核验 |
| `claims` | `id`、`image_id`、`region_id`、`text`、`cites[]`、`cite_status` | 双引用结论、审计 |
| `drills` | `regionOptions`、`descOptions`、`signOptions`、`evOptions`、`teachingNote` | 四步演练 |

### 6.4 DeepWorks 落地清单

| 层 | 配置项 | 输入 | 输出 | 验收 |
| --- | --- | --- | --- | --- |
| 知识库 | `signs` / `guidelines` / `cases` / `regions` / `claims` 五个集合 | `outputs/deepworks-kb-import/` 导入包 | 可检索的段落与元数据 | 检索“磨玻璃影”能召回词条、条款、病例 |
| 技能 1 | `retrieve_sign` | 术语/描述、部位、模态 | 候选词条 + 出处 + 相关病例 | 同义表述可召回；无结果明确返回空 |
| 技能 2 | `dual_align` | 影像线候选 + 指南线候选 | aligned / partial / insufficient / divergent + 缺失条件 | 四种状态都能复现 |
| 技能 3 | `drill_score` | 四步作答 + 标准答案 | 25×4 得分 + 错因 | 与前端计分一致 |
| 技能 4 | `citation_audit` | claim 的双引用 | dual / single / broken / none | 1 条 hash 拦截可见 |
| 工作流 1 | `learning_chain` | 学生问题或病例 | 学 → 迁 → 练 → 用 四段结果 | 每段都有输入输出与回执 |
| 工作流 2 | `teaching_loop` | 教师作业 | 布置 → 学生完成 → 错题聚合 → 讲评 | 班级数据可回看 |
| Agent | 人设与边界 | 多段技能结果 | 一句可核对回答 + 出处 + 缺失条件 | 不输出诊断/治疗建议 |
| 证据 | 运行日志、导入包、配置、测试用例 | — | 可复现材料 | 决赛现场在 DeepWorks 内跑通 |

**Agent 输出模板（固定）**

```
结论：<只描述影像表现与库内对照>
依据：<词条/条款/病例 + 定位符/来源>
缺失：<未满足的适用条件；没有则写“无”>
边界：仅用于教学与研究，不构成诊断意见。
```

### 6.5 失败与降级

| 情况 | 界面行为 | 不允许 |
| --- | --- | --- |
| 检索无结果 | 显示“库内暂无足够依据”，建议换更具体术语 | 猜测或补写定义 |
| 双线只命中一线 | 标 `insufficient` / `partial`，列出缺失条件 | 推断病情 |
| 文献 hash 不一致 | 标 `broken`，不展示为可用证据 | 静默忽略 |
| 缺空间锚点 | 标 `single`，降级 | 补造 bbox |
| 用户未选答案 | 不进入下一步，不自动判分 | 预填答案 |

### 7.1 为什么不是“同一页面换颜色”

- **任务不同**：学生要“学会”，教师要“教会”，医生要“核对”。
- **完成口径不同**：学生看任务完成，教师看班级均分，医生看核验条数。
- **证据密度不同**：学生看解释与易错点，教师看错题聚合，医生看 bbox + 文献 + hash。
- **设备行为不同**：移动端不是缩小版桌面，而是把“一屏一件事”作为约束重新排布。

## 8. 关键交互规范

### 8.1 四步演练

| 步骤 | 分值 | 交互 | 反馈 |
| --- | --- | --- | --- |
| 定位 | 25 | 点击影像分区或分区名 | 正确分区高亮；错误分区标红并给出正确项 |
| 描述 | 25 | 单选描述 | 正确项高亮；错误项标红；给出教学要点 |
| 征象 | 25 | 多选征象 | 漏选/错选分别提示；错选扣分 |
| 依据 | 25 | 单选文献/词条 | 正确依据高亮；给出条款条件 |

- 结果页显示四步得分、总分、错因、解析、来源页、判分运行回执。
- 错因写入本地错题本；学生端可重练，教师端可聚合讲评。
- 医生端结果页提供“去工作台核验”，把演练与真实读片流程接起来。

### 8.2 双引用核验

```
结论 → 空间锚点（分区 bbox） + 文献锚点（摘录 + 定位符 + 版本 + sha256）
     → 双引用完整：可用
     → 缺一条：降级
     → hash 不一致：拦截
```

- 核验动作显式记录，不自动把“打开过”当成“已核验”。
- 工作台支持“并排核验”：点分区 → 看结论 → 看两条锚点。
- 交班摘要只汇总“分区 + 结论 + 出处”，不写诊断。

### 8.3 迁移卡

- 三个问题：换模态定义变了吗？换部位判读重点变了吗？换病种还可能是哪些？
- 每条迁移卡包含：词条、部位/模态、定义、易错点、近邻、跨部位、条款条件、可对照病例。
- 可复制、下载 Markdown、保存到本地记录。

### 8.4 班级与投屏

- 作业表单：任务名、链条、截止日期、病例数、病例组、讲评提示。
- 错题聚合：本地记录 + 演示班级；一键生成讲评清单。
- 课堂投屏：只显示题干与选项，答案后置；不展示诊断结论。

### 8.5 移动端

- 底部 5 键固定；内容区底部留出安全区。
- 顶栏角色下拉，切换后保留移动布局。
- 影像最大高度 46–52vh；分区按钮最小触控面积 40px。
- 表格在移动端横向滚动或卡片化；不强行塞入三栏。
- 桌面 430px 画框用于现场对比，真机 390px 走同一套媒体查询。

### 8.6 运行回执

在三处显示“知识库 → 技能 → 工作流 → Agent”四段：

| 位置 | 四段内容 |
| --- | --- |
| 基础知识问答 | 检索 → 召回 → 对齐 → 生成 |
| 四步演练结果 | 定位 → 描述 → 征象 → 依据 |
| 医生核验 | 空间锚点 → 文献锚点 → hash → 结论 |

运行回执不是装饰，而是让评委看到“这一步用了什么、缺了什么、为什么降级”。

## 9. 数据与合规

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 影像来源 | Wikimedia Commons | CC0 / 公有领域 / CC BY / CC BY-SA |

- hash 不一致的样本保留为“拦截演示”，不删除，证明系统会拒绝不可用证据。
