# DeepWorks 工作流配置单（最终版）

> **两条链路要分开看，不能互相冒充**
> - 本地五步编排（`yingzhi/serve/workflow.py`）：已落地，每次 `/api/ask` 真实执行，
>   `/api/health` 报 `real_workflow=true`，完整证据在 `workflow.json`；
> - 平台可视化工作流（本单要建的那条）：仍需在 DeepWorks 界面人工创建，
>   `/api/health` 单独报 `platform_workflow=false`。
>
> 本单只负责第二条；第一条不依赖本单，也不因为本单没建就变成 false。

> 目标：在 DeepWorks 界面建一条 3 步工作流，证明「知识库 + 技能 + 工作流编排 + Agent 运行」都在平台内跑通。
> 预计 2 分钟。工作流是界面可视化编排，没有开放工具/API/CLI，Agent 不能代建；照下表逐字段填即可。

---

## 0. 建之前先做 30 秒自检

在项目根目录跑这两条，确认技能脚本本身是通的：

```bash
python3 .opencode/skills/radhearing-ask/scripts/ask.py "右肺中野有什么问题" --case CASE-006
python3 .opencode/skills/radhearing-ask/scripts/ask.py "这张片子是不是肺癌" --case CASE-006
```

- 第一条应出现：`右肺中野（RML）`、`left=0.06`、`GL-PNE-02`、`第 68 字起`、`f25ddcf0`
- 第二条应出现：`不能回答`、`超出诊断范围`、替代问法

两条都对，再进界面。脚本不通，工作流一定不通。

## 3. 第 2 步：技能 / Agent 调用

### 形态 A：界面能直接选 Skill（优先）

| 字段 | 填这个 |
| --- | --- |
| 节点类型 | 技能 / Skill |
| 技能名 | `radhearing-ask` |
| 入参 | `question = {{question}}` |
| 超时 | 60 秒 |

### 形态 B：界面只有 Agent 节点

这类节点不会自动跑脚本，必须把脚本命令写进提示词，否则模型会凭记忆编答案。

```
你必须执行本地脚本，不要凭记忆回答。

命令：
python3 .opencode/skills/radhearing-ask/scripts/ask.py "{{question}}"

如果提供了病例号，追加参数 --case {{case_id}}。

要求：
1. 把脚本 stdout 原样作为回答返回，不要改写数字、分区和引用。
2. 输出必须保留 kp_id、字符 offset、校验码前缀。
3. 脚本返回 refusal 时，保留拒答理由和替代问法。
4. 结尾保留非诊断声明。
```

## 5. 验收：三条输入，缺一不可

| # | 输入 | 必须看到 | 看不到说明什么 |
| --- | --- | --- | --- |
| 1 | `右肺中野有什么问题` | `RML`、`left=0.06`、`GL-PNE-02`、`第 68 字起` | 没有 `GL-PNE-02` 或 `第 68 字起` = 模型在编，脚本没被执行 |
| 2 | `这张片子是不是肺癌` | `不能回答`、`超出诊断范围`、替代问法 | 拒答分支没生效 |
| 3 | `这张 CT 有没有脑出血` | 明确拒答，说明只做胸部 X 线 | 范围边界没生效 |

第 1 条是防伪关键：只要出现 `GL-PNE-02` 和 `第 68 字起`，就能证明回答来自库内脚本，不是模型生成。

## 7. 常见失败与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 技能节点选不到 `radhearing-ask` | 项目技能未加载 | 确认 `.opencode/skills/radhearing-ask/SKILL.md` 存在，重开会话 |
| 输出通顺但没有 `GL-PNE-02` | Agent 节点在凭记忆答 | 改用形态 A，或用形态 B 的提示词强制跑脚本 |
| 脚本报错找不到病例 | `case_id` 为空且问题里没有实体 | 固定填 `--case CASE-006` |
| 拒答变成"建议就医" | 提示词被模型自由发挥 | 明确要求"保留脚本的 refusal 原文" |
