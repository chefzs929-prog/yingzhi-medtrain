# 胸片阅片 · 功能重规划（2026-11-20）

> 范围：赛道 B「医学影像知识问答」的阅片主链路。
> 结论：**停止继续铺页面，把资源集中到“胸片（CR 胸部）选片 → 分区定位 → 逐区所见 → 出处 → 结构化阅片记录”这一条链路上。**
> 目标：评委现场随便点一例胸片，看到的每一句话都能在图上找到位置、在来源里找到出处；不知道的明确写“未提及”。

---

## 1. 现状诊断（有证据）

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1 | 功能面铺得太宽 | 主应用 7 个一级入口、3 种角色、4 条链条；另有 `read/` 四页 | 每一条都只做到演示级，评委找不到“主功能” |
| 2 | 胸片样本少且混在 120 例里 | `cases.jsonl` 共 120 例，胸部 CR 仅 23 例；其余为 CT/MR/US/乳腺/骨关节 | 胸片是命题最易验证的模态，却没有被单独组织 |
| 3 | 分区结论是“病例级一句话复制到每个区” | 例：CASE-006 五个分区都写“红箭头指向病变区域”；CASE-036 五个分区都写“30 岁健康男性”，而图注是气胸 | 同一病例的“正常区”和“病变区”给出同一结论，阅片不准确 |
| 4 | 分区粒度不是胸片习惯 | 每例固定 5 区：左右上/下野 + 纵隔；没有中野、肺门、膈下 | 与胸片“六分区 + 纵隔 + 膈下”的教学口径不一致 |
| 5 | 指南引用错位 | 正常胸片的分区结论挂 `GL-LUNGRADS-01`（ACR Lung-RADS，适用于低剂量 CT 筛查） | 看起来有引用，实际适用性不成立 |
| 6 | 自然提问被拒答 | 输入“右肺上野有没有异常？”→ 拒答“未命中 60 条征象词条” | 最基础的胸片问题答不了 |
| 7 | 静态站点上传不可用 | `clinic.js` 上传后走 `/api/vision/region`；GitHub Pages 无后端 | 线上“上传影像”是死路 |
| 8 | 静态站点问答不可用 | 问答依赖 `8800` 的 agent；静态页只提示“请在本地运行” | 评委在公网只能看壳 |
| 9 | 多图/拼接影像被当成单图 | CASE-019 是 A/B/C 多幅拼接；CASE-201 是双幅对照 | 分区框无法对应单一解剖区，结论必然错位 |
| 10 | 入口叙事与主功能不一致 | 首页强调“四链条”，而赛题主链路是“影像 → 定位 → 溯源” | 评委需要自己找核心功能 |

### 1.1 数据层面的硬事实

- `kb/data/cases.jsonl`：120 例；胸部 CR 23 例，其中 2 例多图/双幅拼接（CASE-019、CASE-201）移出阅片队列。
- `kb/data/regions.jsonl`：440 个分区；胸片每例 5 区，坐标是左右上/下野 + 纵隔的矩形。
- `kb/data/claims.jsonl`：434 条结论；胸片结论大量为病例级模板，逐区文本相同。
- `kb/data/grounding_audit.json`：6 个分区被判为全黑/近乎全黑，7 条结论因此被丢弃；说明此前的“自动铺量”已经产生不可用数据。

## 2. 赛题要求 → 最小可用功能

赛道 B 的硬约束只有三条：**核心链路在 DeepWorks 内、现场可实时演示、合规（公开影像 + 非诊断）**。
对应到产品，最基础、最可验证的功能是：

| 编号 | 基础功能 | 验收方式 |
| --- | --- | --- |
| F1 | 选择/输入一张胸片 | 队列可选 21 例；上传库内原图能命中，陌生图明确拒绝 |
| F2 | 在胸片上定位解剖分区 | 点分区或拖框，命中六分区/纵隔/膈下，显示患者侧别 |
| F3 | 给出该分区的所见 | 每个分区有独立文本与状态：异常 / 未见异常 / 来源未提及 / 判读受限 |
| F4 | 每条所见都有出处 | 病例来源页 + 许可 + 分区依据 + 征象词条；不挂不适用的指南 |
| F5 | 能问一个胸片问题 | “右肺上野有没有异常”“有没有气胸”“这张片怎么读”能答；诊断/治疗越界拒答 |
| F6 | 能生成一份阅片记录 | 系统顺序（气管/纵隔 → 肺野 → 肺门 → 心影 → 膈肌肋膈角 → 骨骼软组织 → 导管）逐项所见，可复制/下载 |
| F7 | 明确不知道 | 未逐区描述的病例，写“公开来源未提及，本工具不作推断”，不把“未提及”写成“正常” |
| F8 | 非诊断声明 | 页脚、回答、导出记录三处固定声明 |

**不做**（本阶段）：跨部位泛化、病灶分割、DICOM、真实患者数据、自动诊断/分期/治疗建议、复杂工作流编排。

## 3. 范围收缩

### 3.1 保留并强化

| 模块 | 处理 |
| --- | --- |
| 胸片阅片工作台（`read/clinic.html`） | **重写为唯一主入口**：胸片队列 + 分区叠加 + 系统阅片 + 问答 + 出处 + 导出 |
| 胸片数据（23 例 CR 胸部） | 逐区结构化校正（AI 辅助，待医学审核）；2 例多图拼接移出阅片队列；每例补 SHA-256、质量标记、出处 |
| 征象词条（60 条） | 只作为“这个征象长什么样”的释义与易错点来源，不硬套指南 |
| 报告对照 / 分区图谱 / 组卷 | 保留为辅助页，入口降级；不再扩功能 |
| 主应用四链条 | 保留叙事，但首页与导航把“胸片阅片”放第一 |

### 3.2 降级或隐藏

| 模块 | 处理 |
| --- | --- |
| 非胸片病例（CT/MR/US/MG/PET） | 仍在数据里，但不进胸片队列；页面明确写“当前版本聚焦胸片” |
| 上传陌生影像 | 静态模式只做 SHA-256 精确匹配；匹配不上就拒绝，不猜“最像的一例” |
| Agent 问答 | 本地规则引擎优先；有后端时再叠加 Agent，不作为静态演示的前置条件 |
| 角色/设备矩阵 | 不作为主叙事；保留开发者入口，不在首页强调 |
| 班级/实习任务/题库 | 保留但标注“辅助演示”，不占首屏 |

## 4. 数据设计

新增 `kb/data/chest_reading.json`，由 `kb/scripts/build_chest_reading.py` 从 `cases.jsonl` + 结构化校正表生成。

```json
{
  "case_id": "CASE-036",
  "pose": "PA",
  "quality": "正位片（原图气胸标注）",
  "zones": [
    {"id": "RUL", "name": "右肺上野", "side": "right",
     "coords": [0.06, 0.08, 0.30, 0.25],
     "status": "abnormal",
     "text": "右侧胸腔可见气胸，右肺压缩，肺纹理消失（原图标注）。",
     "sign_ids": ["SIGN-008"], "basis": "原图标注"}
  ],
  "system": [
    {"id": "lungs", "name": "肺野", "status": "abnormal",
     "text": "右侧气胸，右肺压缩（原图标注）。", "basis": "原图标注"}
  ],
  "signs": ["SIGN-008"],
  "caveats": ["来源页文字描述与图注冲突，以图注与影像标注为准，建议人工复核。"],
  "sha256": "...",
  "source_page": "https://commons.wikimedia.org/..."
}
```

### 4.1 状态词只允许四种

| status | 含义 | 界面 |
| --- | --- | --- |
| `abnormal` | 公开来源/图注明确描述异常 | 琥珀色，写具体所见 |
| `normal` | 公开来源明确为正常，或正常病例的解剖对照 | 青绿色 |
| `unmentioned` | 公开来源没有逐区描述 | 灰色，写“未提及，不作推断” |
| `limited` | 投照条件/图像质量导致判读受限 | 蓝色，写受限原因 |

**禁止**把 `unmentioned` 渲染成 `normal`；这是本次重做最重要的一条数据规则。

### 4.2 分区口径

- PA：右肺上/中/下野、左肺上/中/下野、纵隔与心影、膈下，共 8 区。
- LAT：胸骨后、肺门/中区、后肺野/后肋膈角，共 3 区。
- 分区框是**教学分区**，按解剖比例近似，不是病灶分割；界面固定标注。
- 患者侧别：PA 图像左侧 = 患者右侧；LAT 不推断左右。

### 4.3 出处优先级

1. 病例来源页（Wikimedia Commons 文件页）+ 许可 + 作者；
2. 原图标注（箭头、文字、解剖标注）；
3. 本库结构化校正表（逐区文本，AI 辅助，待医学审核）；
4. 征象词条（`signs.jsonl` 的定义、易错点、来源 id）。

**不挂指南条款**，除非能说明该条款适用于胸片且适用条件成立；本阶段一律不挂，避免“有引用但用错”。

## 5. 页面与交互

```
┌ 顶栏：RadioCheck · 胸片阅片   [胸片阅片][图谱][组卷][对照]         ┐
├ 左：胸片队列 21 例 ─┬ 中：影像 + 分区叠加 ─┬ 右：阅片面板 ────────┤
│ 全部/正常/气腔影/气胸 │ 病例头 + 三步链路     │ 分区所见 / 系统阅片   │
│ 积液/结核/结节/其他   │ 影像 + 8 区彩色框     │ 问答 / 出处          │
│ 每行：编号/标题/征象  │ 工具：分区/适应/上传  │ 选中区：状态+文本+依据 │
│ 质量标记             │ 来源与许可            │ 生成/复制/下载记录    │
└──────────────────────┴───────────────────────┴───────────────────────┘
```

交互约束：

- **一次只做一件事**：点分区 → 右栏切到“分区所见”；点“系统阅片”→ 右栏切系统清单；点“问答”→ 右栏切问答。
- **分区颜色即状态**：青绿=未见异常，琥珀=异常，灰虚线=未提及，蓝=判读受限；图例常驻。
- **问答只答当前病例**：问题里出现其他病例编号时提示先切换病例，不跨病例拼答案。
- **导出记录不是诊断报告**：标题固定“胸片阅片记录（教学用，非诊断）”。

## 6. 验收标准（现场可逐条演示）

| # | 检查 | 通过条件 |
| --- | --- | --- |
| A1 | 21 例胸片队列 | 每例可打开，影像 200，无 console error |
| A2 | 每例 8 区（PA）/3 区（LAT） | 分区数量正确，患者侧别正确 |
| A3 | 逐区文本不重复 | 同一病例内，异常区与未提及区的文本不同；不存在“每区同一句” |
| A4 | 正常病例 | CASE-001/034 所有区为 `normal`，系统所见全正常 |
| A5 | 局灶病例 | CASE-006/202 右肺中野、下野 `abnormal`，右肺上野 `unmentioned` |
| A6 | 气胸病例 | CASE-036 右侧三区 `abnormal`，左侧 `unmentioned`，并显示来源冲突提示 |
| A7 | 自然提问 | “右肺上野有没有异常？”→ 有依据的回答，不再因“异常”一词拒答 |
| A8 | 越界拒答 | “是不是肺癌？要不要手术？”→ 明确拒答，说明只做影像表现对照 |
| A9 | 未入库上传 | 任意非库内图片 → 明确“未入库，不能定位/回答”，不猜病例 |
| A10 | 库内上传 | 上传 `case-001.jpg` → SHA-256 命中 CASE-001 |
| A11 | 导出记录 | 含病例、质量、系统所见、分区所见、出处、非诊断声明 |
| A12 | 静态可用 | 只用 `python3 -m http.server`，不依赖 8800/4191 |

## 8. 与评分维度的对应

| 评分维度 | 本次重做提供的证据 |
| --- | --- |
| 项目背景 · 竞品 | PACS 只给报告字段；通用问答无分区；本页每条所见挂图上分区与来源 |
| 项目背景 · 可行性 | 纯静态可跑、21 例逐区校正、SHA-256 可复现、无真实患者数据 |
| 项目背景 · 创新性 | “状态四值”把“未提及”与“正常”分开；来源冲突显式暴露（CASE-036） |
| 实用性 · 真实任务 | 选片 → 点区 → 读所见 → 看依据 → 导出记录，5 步内完成 |
| 实用性 · 流程 | 一次只做一件事；分区颜色即状态；问答只答当前病例 |
| 实用性 · 样例/反馈 | 21 例样例 + 12 项验收 + 可引用的失败案例（未入库上传） |
| 迭代记录 | 本文的现状诊断 → 数据规则 → 验收表，可逐条对照 |
| 最终成品 | 单页主链路、静态可复现、非诊断声明三处固定 |
