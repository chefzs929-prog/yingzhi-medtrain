# 外接模型评估：智能读片 + 医学知识问答

> 评估日期：2026-11-19。价格与模型版本以各厂商官网为准；本文只给选型逻辑与可执行改造点。

## 0. 结论先行

1. **读片不要指望一个通用 VLM 端到端做完。** 可行的是「VLM 出结构化 finding + 粗框 → 分割模型出轮廓 → 模板/规则做分区 → 库内引用兜底」。端到端报告生成可以加，但只能作为第二意见。
2. **知识问答的瓶颈不是模型，是检索。** 通用强模型 + 本地库 + PubMed 已经够用；换更贵的模型不会显著提升引用准确率，补向量检索和条款映射才会。
3. **合规优先级高于效果。** 患者影像出境是硬约束，首选境内 API 或本地部署；DICOM 必须先脱敏。
4. **当前代码已经隔离了模型层**，换模型基本只改 `yingzhi/serve/.env`；真正要改的是结构化输出、DICOM 预处理、分割与评测。

## 1. 当前基线

### 1.1 已经具备

| 能力 | 现状 | 位置 |
| --- | --- | --- |
| 模型路由 | 有图走 vision，无图走 text，OpenAI 兼容 | `yingzhi/serve/llm.py` `Router` |
| 影像定位 | VLM 输出 bbox，前端框选兜底 | `llm.py` `SYSTEM_PROMPT`、`vision.py` `extract_bbox` |
| 分区 | 库内精确标注 + 陌生图通用模板 | `atlas.py`、`kb/data/atlas_templates.json` |
| 知识问答 | agent + `retrieve-sign` + 本地词条库 | `gateway.py`、`.opencode/skills/retrieve-sign` |
| 网络文献 | PubMed E-utilities，双引用 | `litsearch.py` |
| 可校验性 | 引用 id 必须存在，否则丢弃计数 | `llm.py` `valid_ids`、`main.py` `cites_from_text` |

### 1.2 真实缺口

| 缺口 | 影响 | 严重度 |
| --- | --- | --- |
| 不支持 DICOM | 医院真实数据进不来，只能 JPG/PNG | 高 |
| 只有 bbox，没有 mask | 无法算面积、形态、密度，报告只能写“某处见异常” | 高 |
| 单图、单帧 | CT/MR 序列无法读，胸片以外的场景受限 | 高 |
| 检索是关键词，不是向量 | 同义表述召回差，指南条款覆盖不足 | 高 |
| `Client.chat` 固定 `temperature=0.2`、`max_tokens=900` | 结构化输出不稳定，长报告会被截断 | 中 |
| 无 JSON schema / 重试 | bbox 解析靠正则，失败即丢 | 中 |
| `extract_bbox` 用 `_SCALE_HINT` 猜 0-1 还是 0-1000 | 不同厂商约定不同，容易错 | 中 |
| 无评测集 | 换模型无法判断变好还是变差 | 高 |

> 已修：有图但 vision 未配置时，`Router.pick()` 退回 text 却仍发 `image_url`，纯文本模型会 400。现在改为丢弃图片并显式声明“未读取影像”。

## 2. 两条能力线的本质差异

| 维度 | 智能读片 | 医学知识问答 |
| --- | --- | --- |
| 输入 | 像素，高维、连续 | 文本，离散、可检索 |
| 失败模式 | 漏诊、错位、编造病灶 | 编造引用、过时指南 |
| 可校验性 | 框/轮廓可算 IoU；报告难自动校验 | 引用 id 可查；语义相关性难自动校验 |
| 数据要求 | 需要带标注的影像；DICOM 预处理 | 需要结构化指南/词条；更新频繁 |
| 模型瓶颈 | 视觉定位与分割能力 | 检索召回与重排 |
| 合规风险 | 高（患者影像） | 中（问题文本可能含 PHI） |

结论：**两条线要分开选型、分开评测**，不要用一个“全能医疗大模型”同时解决。

## 3. 读片模型评估

### 3.1 能力分层

| 层级 | 输出 | 可用方案 | 现状 |
| --- | --- | --- | --- |
| L1 描述 | 解剖结构、密度、边缘、分布 | 通用 VLM | 已支持 |
| L2 定位 | bbox / point | 通用 VLM + JSON schema | 部分支持，缺重试 |
| L3 分割 | mask / 轮廓 | MedSAM2、SAM2、nnU-Net | 未接 |
| L4 结构化报告 | Findings / Impression | CheXagent、MAIRA-2、通用 VLM | 未接 |
| L5 分区 | 解剖分区标签 | 模板 + 规则（已有） | 已支持 |

**建议只把 L1/L2/L5 放在主链路**：可校验、可解释、失败可降级。L3 作为增强，L4 作为第二意见。

### 3.2 候选矩阵

| 方案 | 类型 | 中文 | bbox | 分割 | 部署 | 适用判断 |
| --- | --- | --- | --- | --- | --- | --- |
| Qwen3-VL-Plus / Qwen2.5-VL-72B | 通用 VLM | 强 | 支持 | 无 | 境内 API / 自部署 | **首选**：中文好、OpenAI 兼容、支持 grounding |
| GLM-4.5V | 通用 VLM | 强 | 支持 | 无 | 境内 API | 备选，适合已有智谱账号 |
| InternVL3 | 开源 VLM | 中 | 支持 | 无 | 自部署 | 数据不出内网时选它 |
| Gemini 2.5 Flash | 通用 VLM | 中 | 支持 | 无 | 境外 API | 便宜、多图强；需评估出境 |
| GPT-4o / 4.1 | 通用 VLM | 中 | 支持 | 无 | 境外 API | 稳但贵；适合对照实验 |
| MedGemma 27B | 医学 VLM | 弱 | 有限 | 无 | 自部署（GPU） | 胸片/病理/皮肤有优势，中文与工程化弱 |
| CheXagent | 胸片报告 | 无 | 无 | 无 | 自部署 | 仅英文胸片，研究用途；可做第二意见 |
| MAIRA-2 | 胸片 grounding + 报告 | 无 | 有 | 无 | 研究许可 | 胸片定位强，但不能直接商用 |
| MedSAM2 / SAM2 | 分割 | - | 有 | 强 | 自部署 | 把 bbox 升级成 mask 的最短路径 |
| nnU-Net | 分割 | - | - | 强 | 需训练 | 有标注数据后，精度上限最高 |

### 3.3 推荐组合

**主链路（可解释、可降级）**

```
影像 → DICOM/PNG 预处理 → Qwen3-VL 出 {findings, bbox} →
MedSAM2 用 bbox 做 prompt 分割 → 模板/规则定分区 →
本地库引用 + PubMed 文献 → 四段式回答
```

**第二意见（可选，答辩加分）**

```
胸片 → CheXagent / MAIRA-2 → 英文 Findings/Impression →
与主链路结果做差异对比，只展示“不一致点”，不合并成结论
```

理由：

- Qwen3-VL 的中文和 grounding 足够，且 OpenAI 兼容，接入成本最低；
- MedSAM2 零样本可用，不需要训练，能把“框”变成“轮廓”；
- CheXagent/MAIRA-2 只在胸片、英文场景强，直接当主链路会牺牲中文与可解释性。

## 4. 知识问答模型评估

### 4.1 为什么模型不是瓶颈

当前回答质量取决于三件事：

1. **能不能检索到**：关键词匹配对同义表述召回差；
2. **检索到的东西对不对**：指南条款是否覆盖问题；
3. **引用是否可核验**：id 存在不等于语义相关。

换 GPT-5 或 Claude 不会解决 1 和 2。实测中 agent 已经能稳定给出 3 条本地引用 + 4 条 PubMed 文献，瓶颈在“库内覆盖”。

### 4.2 候选矩阵

| 方案 | 中文 | 长上下文 | 工具调用 | 成本量级 | 适用判断 |
| --- | --- | --- | --- | --- | --- |
| DeepSeek-V3.x | 强 | 64K+ | 支持 | 低 | **首选**：中文医学语料好，便宜 |
| Qwen3-Max | 强 | 长 | 支持 | 中 | 备选，与视觉同一厂商，账单合并 |
| GLM-4.6 | 强 | 长 | 支持 | 中 | 备选 |
| Kimi K2 | 强 | 很长 | 支持 | 中 | 长指南全文场景 |
| GPT-5 / Claude Sonnet 4.5 | 中 | 长 | 强 | 高 | 对照实验；需评估出境 |
| 医学专用模型（Med-PaLM 类） | 弱 | - | - | - | 不推荐做主模型：时效性差、不可引用、多不可用 |

### 4.3 推荐组合

```
通用强模型（DeepSeek/Qwen） + 本地库关键词检索 + 向量检索（bge-m3） +
PubMed + 引用存在性校验 + 无依据拒答
```

**不建议**把医学专用模型当主模型：指南每年更新，专用模型的冻结知识很快过时；而且它们通常不能给出可核验的条款 id。

## 6. 评测方案

### 6.1 读片

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 分区命中率 | 模型框与人工框 IoU ≥ 0.3 且分区一致 | ≥ 85% |
| 框稳定性 | 同图 5 次，IoU 方差 | ≤ 0.02 |
| 分割 Dice | mask 与人工轮廓 | ≥ 0.75（有标注后） |
| 报告一致性 | CheXbert 标签 F1 或医生盲评 | ≥ 0.7 |
| 拒答率 | 非医学图/模糊图应拒答 | ≥ 90% |

### 6.2 知识问答

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 引用准确率 | 引用 id 存在且与问题语义相关 | ≥ 90% |
| 无依据拒答率 | 库内无覆盖时明确说“未覆盖” | ≥ 95% |
| 首 token 延迟 | 从请求到第一个 delta | ≤ 3s |
| 总耗时 | 含检索与文献 | ≤ 15s |

### 6.3 对照实验

同一批题，跑三组：

1. 关键词检索 + DeepSeek；
2. 向量检索 + DeepSeek；
3. 向量检索 + 更强模型（GPT/Claude）。

如果 2 比 1 提升明显、3 比 2 提升不明显，就证明“瓶颈在检索”，可以把预算放在数据而不是模型上。

## 8. 成本量级（估算，以官网为准）

| 场景 | 单次消耗 | 量级 |
| --- | --- | --- |
| 单张胸片 1024px | 约 1–1.5k image tokens | ¥0.002–0.01 / 张 |
| 一次知识问答 | 约 2–4k tokens（含检索） | ¥0.01–0.05 / 次 |
| 1000 张/天 | 读片 + 问答 | 每月数百至数千元 |
| 自部署 7B VLM | 16–24GB VRAM | 一张 4090/A10 可跑 |
| 自部署 27B 医学 VLM | 48GB+（bf16） | 需 A100/多卡 |

真正的成本不在 token，而在**评测与数据标注**：20 例胸片的人工框和 50 道知识题，至少 1–2 人天。

## 9. 风险与合规

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 影像出境 | 患者影像属敏感个人信息 | 首选境内 API 或本地部署；出境前做安全评估 |
| PHI 泄露 | DICOM 含姓名、ID、生日、机构 | 预处理阶段剥离/替换，日志不落原图 |
| 幻觉 | VLM 会编造病灶位置 | 框必须可回显；分区必须模板/标注命中；无依据拒答 |
| 过度宣称 | “AI 读片”被理解为诊断 | 界面固定声明“教学与研究，不构成诊断” |
| 供应商锁定 | 换模型要改代码 | 已用 OpenAI 兼容层；新增能力走适配器 |
| 指南过时 | 模型知识冻结 | 指南以库内版本为准，模型只组织语言 |

## 10. 诚实边界

- 本文的模型能力判断基于公开资料与工程经验，**没有在本机做多模型横评**；上表是选型建议，不是实测排名。
- 当前本机未配置视觉模型，读片链路只验证了“框选 + 模板分区”，**自动出框尚未实测**。
- 分区模板来自 981 条标注聚合，26 个模板中 9 个只有 1–2 例，不能当人工标注。
- 知识问答的引用只校验 id 存在，**不校验语义相关性**；这是下一步要补的评测项。
- 成本为量级估算，实际以厂商计费与图片分辨率换算为准。

## 11. 实施进展（2026-11-19）

按本文 P0/P1 已落地的改动与实测数字。

### 11.1 已落地

| 项 | 改动 | 验证 |
| --- | --- | --- |
| 结构化输出 | `Client.chat` 支持 `temperature/max_tokens/response_format/retries`；`Answerer.structured()` JSON 解析失败重试一次 | 单测：第一次非 JSON，第二次去掉 `response_format` 后成功 |
| 有图无 vision | 不再给文本模型发 `image_url`，prompt 明确「未读取影像」 | 单测：content 为纯文本，含「未读取影像」 |
| bbox 解析 | 支持 `[x,y,w,h]`、`[x1,y1,x2,y2]`、千分制、Gemini `box_2d`、`{"x":..}` | 5 组样例全部通过 |
| 陌生影像 | `/api/vision/region` 先结构化出 `{bbox, modality, body_part, view}`，再匹配模板 | 框选 + PA 模板：右肺上野，覆盖 100% |
| 结构化报告 | 新增 `/api/vision/report`，输出 findings/impression/limitations + 库内引用 | 未配视觉模型时明确 `vision_unavailable` |
| 分割接口 | 新增 `segment.py` + `/api/vision/segment`，未装依赖返回 `segment_unavailable` | 实测返回 `missing_dependency`，不返回假 mask |
| 检索召回 | 名称/别名精确命中 + 字符二元组 Dice 兜底（阈值 0.45） | 「磨玻璃密度影」能命中「磨玻璃影」；「肾囊肿」不误命中「肾积水」 |
| 引用校验 | `citation.relevance=direct/related/off`，同部位扩展升级为 related | 磨玻璃影：1 direct + 2 related + 0 off |
| 无依据标记 | `done.ungrounded=true`，前端提示「没有库内引用」 | 3 条无引用回答会被标出 |

### 11.2 实测数字

**模板留一法**（`kb/scripts/eval_template.py`）：

```
leave-one-case-out  n=940  hit=913 (97.1%)  wrong=0  cross=0  miss=27
```

注意：这是「同 atlas 其他病例的模板」定位当前病例人工框，病例间构图高度同构，
**不代表陌生文献影像的真实准确率**。真实场景构图差异更大，应视为上限参考。

**知识问答**（`kb/scripts/eval_kb.py`，20 题）：

```
grounded=17  refused=0  ungrounded=3  off_cites=14  avg=17928ms
```

- `grounded` 17/20：有库内引用；
- `ungrounded` 3/20：肝血管瘤、肺门增大、肠梗阻——库内覆盖不足，模型仍回答了，但没有引用；
- `off_cites` 14：引用与问题部位/主题不符，前端标「弱相关」；
- 平均 17.9s，超过 15s 目标，瓶颈在 agent 检索与生成。

### 11.3 仍然没解决

| 项 | 现状 | 下一步 |
| --- | --- | --- |
| DICOM | 不做，已写入 README 未来方向 | 需要时按 pydicom → 窗宽窗位 → 脱敏接入 |
| mask | 只有接口，无权重 | 装 `torch + sam2`，配 `YZ_SEG_CHECKPOINT` |
| 语义检索 | 仍是关键词 + 二元组 | 接 bge-m3 做混合检索 |
| 拒答 | 3 条无依据回答没有主动拒答 | 在 agent prompt 或后置校验里强制「无引用必须说明」 |
| 引用语义 | `related` 只保证部位一致 | 需要 embedding 或人工抽检 |
