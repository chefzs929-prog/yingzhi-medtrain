## 2. 语料构成

### 2.1 来源与合规

- 全部来自 Wikimedia Commons，许可为 CC0 / 公有领域 / CC BY / CC BY-SA；
- 只下载 1000px 缩略图，原图链接与许可原文保存在 `cases.source_page` / `license` / `artist`；
- 采集脚本按分类抓取，标题含姓名、病历号等线索的标 `privacy_flag`，标 `auto_screened` 待人工复核；
- 采集过程触发过 Wikimedia 429 限流，脚本已改为低速 + 指数退避，清单见 `kb/_candidates/*.json`。

### 2.2 为什么是这 120 例

不是随机抽样，而是按「常用体位」配额选取：

| 部位 | 例数 | 说明 |
| --- | --- | --- |
| 胸部 | 39 | PA 胸片为主，含侧位、胸部 CT（局部级） |
| 四肢 | 24 | 膝、手、足、肘、腕、肩、骨盆 |
| 乳腺 | 17 | MLO 位，图像内分区 |
| 头颅 | 12 | MR 轴位为主，图像内分区 |
| 超声 | 10 | 甲状腺，探头相对分区 |
| 腹部 | 5 | CT 轴位，图像内分区 |
| 脊柱 | 5 | 颈椎、腰椎侧位 |

### 2.3 分区从哪来

| 方式 | 覆盖 | 说明 |
| --- | --- | --- |
| 人工标注 | CASE-001 / 006 / 011，共 21 个分区 | 沿用 v1.1，不覆盖 |
| 体位模板 | 其余 117 例，共 575 个分区 | 按 `pose_class` 套用模板坐标 |

模板是「教学示意」，不是放射科医师逐例勾画。每个分区带 `derivation`：

```json
{"mode":"template","template_id":"ATLAS-CHEST-PA-6","residual":0.0,
 "method":"template_apply","confidence":0.62}
```

### 2.4 双引用怎么成立

每条自动 claim 由「分区 × 征象」模板实例化：

```
{分区名}区域解剖范围为{解剖边界}。库内关联征象包括{征象名}；
本条目只作分区与征象对照，不构成诊断。
```

- 空间锚点：分区 `coords` 内缩 1% 的 bbox；
- 文献锚点：`signs.jsonl` 的 `appearance` 原文 + `sha256` 前 8 位 + 定位符 + 来源链接；
- 校验器实算 hash，不一致即 `broken`（CLM-007 是保留的失败样本）。

**不做的三件事**：不生成诊断结论、不改写文献摘录、不对未标注区域作推断。

## 3. 场景适配：两种界面为什么这样设计

《知识库搭建方案》定了三条硬约束：**来源可溯、缺失即提示、不构成诊断**。教学与临床对这三条的用法不同：

| 维度 | 教学场景 | 临床场景 |
| --- | --- | --- |
| 核心任务 | 建立「分区—征象」的对应关系 | 快速核验「这条结论凭什么」 |
| 主要动作 | 点分区、读讲解、做自测 | 拖框定位、看双锚点、查审计 |
| 证据等级 | 弱化，作为学习提示 | 前置，作为筛选条件 |
| 信息密度 | 低，一屏一个分区 | 高，一屏一张表 |
| 失败处理 | 解释「为什么没命中」 | 直接给出拦截原因 |
| 视觉语言 | 暖白、衬线、圆角、留白 | 深色、等宽、直角、紧凑 |

一句话：**教学版把「不确定」讲清楚，临床版把「不确定」标出来。**

## 4. 教学版 `/teach`

### 4.1 信息架构

```
顶栏：课程名 + 学习进度 + 场景切换
左栏：7 个章节 → 章节内病例列表（可筛选）
中栏：大图 + 可点分区（标签常显）
右栏：讲解卡（分区名 / 解剖边界 / 关联征象 / 文献摘录 / 双引用状态）
底栏：上一例 / 分区开关 / 自测 / 标记已学 / 下一例
```

### 4.2 三个教学设计

**① 章节优先，而不是检索优先。**
初学者不知道「CASE-037」是什么，但知道「我想学胸部」。所以左栏第一层是章节，第二层才是病例。

**② 讲解卡固定四段。**
分区是什么 → 边界在哪 → 库内关联哪些征象 → 文献原文怎么说。顺序固定，降低认知负担。

**③ 自测只考「分区—征象」对应。**
题目由后端按病例确定性生成（同一病例每次题目一致），只问两类：

- 给解剖边界，问是哪个分区；
- 给分区，问库内关联的征象。

答错时高亮图上对应分区，并说明「以 signs.jsonl 的 body_part 归属为准，不代表本例一定出现该征象」。

### 4.3 视觉

暖白纸感（`#f6f1e8`）、墨绿主色、陶土色高亮、宋体标题、18px 圆角。分区框用细线 + 低透明度填充，选中转陶土色。图像内分区（CT/MR/超声/乳腺）用**虚线框**，与解剖分区区分。

## 5. 临床版 `/clinic`

### 5.1 信息架构

```
顶栏：搜索 + 证据等级筛选 + 全局门禁统计 + 场景切换
左栏：病例表格（编号 / 部位·模态 / 分区数 / 双引用数 / 等级）
中栏：影像 + 拖框定位 + 分区叠加 + 缩放
右栏：定位 / 证据 / 审计 三个 Tab
```

### 5.2 三个临床设计

**① 框选是主交互，不是点选。**
临床习惯是「我看这块」，不是「我点这个标签」。拖框后按覆盖率与纯度打分，返回命中分区；跨区时给候选并提示缩小范围。

**② 证据面板逐项列锚点。**
空间锚点显示 `image_id / region_id / bbox / atlas`；文献锚点显示 `doc_title / version / locator / excerpt / sha256`，并给出「✓ 一致 / ✗ 不一致」。门禁问题单独成块，不藏在折叠里。

**③ 审计是常驻能力，不是调试页。**
全量 582 条按 `dual / single / broken` 聚合，表格列出 claim、图号、状态、文献、问题码。拦截条目一眼可见。

### 5.3 视觉

深色（`#0b1015`）、青绿主色（`#4ec9b0`）、等宽数字、6px 直角、密集表格。证据等级用 B/C 色块前置在表格里，便于快速扫读。

## 6. 共用与差异

| 能力 | 教学版 | 临床版 |
| --- | --- | --- |
| 数据源 | `/api/chapters` `/api/lesson/{id}` | `/api/cases` `/api/cases/{id}` `/api/audit` |
| 定位 | 点分区（模板坐标） | 拖框（`/api/locate` 实算覆盖率） |
| 双引用 | 讲解卡展示摘录 | 证据面板展示锚点 + hash 校验 |
| 证据等级 | 角标提示 | 表格筛选 + 面板显示 |
| 门禁 | 只显示当前分区状态 | 全局统计 + 全量审计 |
| 缩放 | 无（自适应大图） | 0.5×–3× |
| 学习进度 | localStorage | 无 |

**共用**：同一份 `claims.jsonl`、同一套 `evaluate()` 门禁、同一份 `disclaimer`。

## 8. 质量边界（必须一起说）

| 项 | 现状 | 影响 |
| --- | --- | --- |
| 模板坐标 | 按解剖比例人工估计 | 用于交互与数据结构验证，不作为标注质量证明 |
| 体位判定 | 标题/分类关键词 | 侧位/斜位已降级为图像内分区，但仍有误判可能 |
| 征象关联 | 按 `body_part` 取词条 | 局部级可能出现「图像上部 → 骨髓水肿」这类弱关联 |
| 证据等级 | 117 例为 C | 界面已标「待复核」，不计入可信统计 |
| 隐私核验 | `auto_screened` | 需人工复核，未核验前不作为正式引用 |
| 脊柱样本 | 仅 5 例 | 公开源脊柱图有限，章节内容偏薄 |
| 临床定位 | 不推断左右侧别（local 级） | 符合能力边界，但不是临床级解剖定位 |

> 本工具仅用于教学与研究，不构成诊断意见，不能替代医师判断。

```bash
curl -s localhost:4191/api/meta
curl -s localhost:4191/api/chapters
curl -s localhost:4191/api/lesson/CASE-001
curl -s -X POST localhost:4191/api/locate \
  -H 'Content-Type: application/json' \
  -d '{"image_id":"CASE-060","bbox":[0.3,0.1,0.3,0.2]}'
```

数据完整性检查项：图片存在、region→case、claim→region、doc hash 一致（除 CLM-007）。
