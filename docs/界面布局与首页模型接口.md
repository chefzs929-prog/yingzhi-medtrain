> 版本：v3.1 · 2026-11-16
> 对应实现：`medtrain/app/core.js`（骨架）、`medtrain/app/landing.js` + `body-model.js`（首页）、`medtrain/build.py`（入口生成）

## 1. 结论

| 决策项 | 结论 |
| --- | --- |
| 导航骨架 | **D · A+C 响应式**：左侧栏常驻，≥1280px 自动展开右侧证据栏，<900px 收为底部 tabbar |
| 首页形态 | 独立产品首页 `index.html`，含人体部位入口；**3D 模型接口已预留，当前 SVG 占位** |
| 入口策略 | 对外 **单入口**（`app.html`）；固定角色/设备入口下沉到 `dev/`，供评审对照 |

## 4. 证据栏的三条规则

1. **只读已有数据**：不在证据栏发起请求，也不推算缺失值。
2. **不张冠李戴**：一个征象在关联病例里找不到含自己的结论时，显示「该征象暂无专属引用结论」，
   不回退到同病例的其他结论。当前 60 个征象中 26 个有专属引用。
3. **演练不剧透**：`#/drill` 下作答前只显示题目病例与影像许可，作答后才展开证据。

## 5. 首页人体模型接口

### 5.1 当前状态

```
mode = "svg-fallback"
note = "3D 模型接口已预留，当前为 SVG 占位（可点击，非 3D 渲染）"
```

首页右上角徽章会如实显示 `SVG 占位 · 3D 接口已预留`，接上适配器后自动变为 `3D 适配器 · <name>`。
**不要在接入前把这个徽章改成「3D 人体」**——它是当前能力的对外声明。

### 5.2 契约

```js
YZ.BodyModel = {
  VERSION: "1.0",
  CONTRACT: ["mount(el, opts) -> handle", "handle.highlight(regionId)",
             "handle.reset()", "handle.resize()", "handle.dispose()"],
  status(),          // { contract, mode, adapterName, ready, note }
  mount(el, opts),   // -> handle
}
```

`opts`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `regions` | `[{id, name, count}]` | 5 个部位，`id` 为 `REG-CHEST` 等，`count` 为词条数 |
| `onSelect` | `(regionId, region) => void` | 点击回调，取消选中时 `regionId` 为 `null` |
| `active` | `string \| null` | 初始选中 |

`handle` 需实现 `highlight / reset / resize / dispose`，`dispose` 必须能重复调用。

### 5.3 接入 3D 适配器

在 `landing.js` 执行前挂上适配器即可，**不需要改首页其余代码**：

```html
<script src="data/kb.js"></script>
<script>
  // 例如 Three.js 适配器
  window.YZ_BODY_MODEL_ADAPTER = {
    name: "three-body",
    mount(el, opts) {
      // 1. 在 el 内创建 canvas
      // 2. 加载人体模型（glb），按 opts.regions 建立 5 个可点击区域
      // 3. 点击时调用 opts.onSelect(regionId, region)
      // 4. 返回 { highlight, reset, resize, dispose }
    },
  };
</script>
<script src="body-model.js"></script>
<script src="landing.js"></script>
```

适配器 `mount` 抛错时自动回落 SVG，原因写入 `handle.fallbackReason`，首页会把它显示在模型下方。

### 5.4 为什么先做接口而不是先做 3D

- 人体模型是**交互入口**，不是知识来源；5 个部位与 `REG-CHEST` 等 id 的映射才是必须稳定的部分。
- 3D 资源体积大、移动端性能差，评审现场网络不可控；SVG 占位保证任何机器都能打开。
- 接口先定，模型后换，首页布局、右侧面板、跳转链接都不用重写。

## 病例工作台：分区标注与隐藏

医生端「用 · 病例工作台」的影像上叠着人工标注的解剖分区框。早期把分区名直接写在框内，
小框（一张胸片 8 个分区）里文字互相压住，读不清。

现行规则：

| 规则 | 实现 |
| --- | --- |
| 图上只留编号 | `.bbox.mark span` 居中显示 1…N，字号 9.5px |
| 名称进图例 | 图下方 `.wb-legend` 每项 = 编号 + 分区名 + 该区结论条数 |
| 双向可选 | 点框或点图例都写 `state.regionId`，选中的框变绿、图例高亮 |
| 一键隐藏 | `[data-act="regions"]` 切 `state.showRegions`；隐藏时整层 overlay 不渲染，不留隐形热区 |
| 隐藏后仍可用 | 图例保留，按名称选分区不受影响；底部说明改为「分区框已隐藏」 |
| 边界不变 | 始终标注「编号为人工标注解剖区，不是病灶分割」 |

医生端进入工作台时会自动收起右侧证据栏（`syncEvidenceForView`）：工作台本身已有病例队列与结论列，
再叠一列重复内容会把影像压到 236px 宽，分区框根本放不下编号。收起后影像 461px 宽；用户仍可点折叠按钮展开。
