## 三、缺陷清单（按严重度）

### P0-1 课堂同步“删除不生效”，教师删完会被同步复活

**现象**：教师端有“移除学生 / 删除作业 / 删除小组 / 删除帖子”四个操作（[classroom.js](kb/app/classroom.js#L204)），但同步层只做“并集追加”，没有任何删除传播。

**证据**（本地实测，8820 协议同源）：

```
1) 初始写入： 1 帖 / 1 生
2) 删除后同步：帖子 1 学生 1 作业 1   ← 全部复活
```

**根因**：前后端两套 merge 都只增不删。
- 前端 [classroom-sync.js](kb/app/classroom-sync.js#L67) `mergeInto` 只 `push`，不比对删除；
- 服务端 [classroom_server.py](kb/server/classroom_server.py#L77) `merge` 从服务端快照出发，客户端“少了”的对象不会被移除；
- 主服务复用同一逻辑（[main.py](yingzhi/serve/main.py#L869) `_sync_merge`）。

**影响**：多端课堂一旦开启同步，删除操作永久失效；学生会看到已被移除的作业，帖子“已解决/已删除”反复出现。

**建议**：引入软删除（`deletedAt`）或显式墓碑列表，前后端同步比较；验收补“删除后同步不复活”用例。

### P0-2 独立同步服务的口令形同虚设，`/api/reset` 可被任意清空

**现象**：README 写“服务端设 `YZ_SYNC_TOKEN` 后必须带口令”（[README.md](README.md#L91)），但独立的 `classroom_server.py` **完全不读该环境变量**。

**证据**（服务以 `YZ_SYNC_TOKEN=secret123` 启动）：

```
3) 不带口令读取快照： True
4) 错误口令 reset： True
5) reset 后班级数： 0
```

**根因**：
- [classroom_server.py](kb/server/classroom_server.py#L197) 的 `do_POST` 没有任何 token 校验；
- [classroom_server.py](kb/server/classroom_server.py#L212) 的 `/api/reset` 无鉴权、无口令；
- CORS 固定 `Access-Control-Allow-Origin: *`，内网任意网页可读取含学生姓名的快照。

主服务 `main.py` 有 `_sync_token_ok`，所以问题只在“方式一：独立同步服务”，但 README 没有区分。

**影响**：课堂数据（学生姓名、答题、成绩）可被同网段任意请求读取或清空；若按 README 用隧道演示，等于公网裸奔。

**建议**：把 `_sync_token_ok` 下沉到 `classroom_server.py`；`/api/reset` 强制要求口令并默认关闭；CORS 收敛到配置的来源；README 明确两种方式的口令差异。

### P0-3 “62% 模型严格一致”口径失真，冲突例几乎都是阈值卡线

**现象**：评测页展示“62% 模型严格一致”（[eval.html](kb/app/eval.html)），但 6 例 `conflict` 全部是“人工标注全部正常”的病例，模型最高分仅 0.509–0.615，紧贴 0.5 阈值。

**证据**：

| 病例 | 判定 | 最高分 | 次高分 | 异常区数 |
| --- | --- | --- | --- | --- |
| CASE-002 | conflict | 0.530 | 0.505 | 0 |
| CASE-003 | conflict | 0.515 | 0.507 | 0 |
| CASE-033 | conflict | 0.615 | 0.570 | 0 |
| CASE-034 | conflict | 0.509 | 0.412 | 0 |
| CASE-041 | conflict | 0.597 | 0.526 | 0 |
| CASE-047 | conflict | 0.564 | 0.503 | 0 |

**根因**：
- 判定用硬编码 `score >= 0.5`（[build_model_probe.py](kb/scripts/build_model_probe.py#L119)），没有校准；
- 分母混入了 **CASE-002 正常侧位片**（模型主要在 PA/AP 上训练）和 **CASE-003/033/034/041/047 解剖标注图**——这 5 例正好也是双源对照无报告、问答无原文锚点的同一批；
- `consistent` 里还有 0.527/0.593/0.600 的弱一致。

**影响**：这个数字既不说明模型能力，也不说明标注质量，却作为“交叉检验”对外展示，评委很容易追问后失分。

**建议**：排除侧位片与标注示意图（或单列）；改用校准阈值 + 阈值敏感性表；报告里写清“conflict 全部为正常片弱信号”。

### P1-1 评测脚本 `parse_region` 重复定义，且与线上引擎不一致

**现象**：`run_eval.py` 里 `parse_region` 定义了两次，第二次覆盖第一次，语义不同。

**证据**：

```
右肺中野是什么情况  引擎='右中'  评测='中'    ← 丢左右
左肺中野是什么情况  引擎='左中'  评测='中'    ← 左被当成右
右下肺有什么        引擎='右下'  评测=''      ← 分区分完全丢失
```

- 正确实现：[ask_engine.py](kb/scripts/ask_engine.py#L48)、[ask-core.js](kb/app/ask-core.js#L38)
- 覆盖实现：[run_eval.py](kb/scripts/run_eval.py#L67)（重复定义在 [L56](kb/scripts/run_eval.py#L56)）

**影响**：
- 脚本头声称“与 JS 版本逐行对齐”，不成立；
- 现有 69 条评测**没有一条能区分左右侧解析**（实测 kind 级差异 0 条、仅 1 条分数变化），所以 1.0 是“碰巧仍通过”，不是“测对了”；
- 后续任何调参都会被这套错算法带偏。

**建议**：删掉重复定义，直接 import `ask_engine.parse_region`；评测集补左右侧对照问法；CI 增加 JS/Python 一致性门禁。

### P1-2 40 条分区问答没有原文锚点，双引用静默缺失

**现象**：`ask_bank.json` 中 314 条可答项里有 40 条 `citation: null`，全部集中在 5 例（CASE-003/033/034/041/047）× 8 个分区。

**证据**：

```
可答: 314   有 quote: 274
无引用原文 40 条 kind 分布: {'zone': 40}
case 分布: {CASE-003: 8, CASE-033: 8, CASE-034: 8, CASE-041: 8, CASE-047: 8}
```

前端 [ask.html](kb/app/ask.html#L217) 用 `if(item.citation)` 判断，`null` 时整块“依据原文”直接不渲染，只留“出处：公开来源说明”，用户无从知道为什么没有原文。

**影响**：README 正文写“每条命中给两条引用链”（[README.md](README.md#L105)），与口径表“不要再说每条都带 E1+L1”（[数字口径表](docs/数字口径表.md#L48)）自相矛盾；这 5 例恰好是演示时最容易被点到的“解剖标注/未覆盖主题”病例。

**建议**：要么补齐来源原文，要么在 UI 明确显示“本条无原文锚点，仅库内分区标注”，并在 README 改成“有原文的条目给 L1，其余仅给 E1”。

### P1-3 教师备课包缺 E1/L1 证据锚点，验收失败

**现象**：备课包已生成“### 证据锚点”，但内容是“影像位置：… / 文献来源：…”，没有问答页统一的 `E1：` / `L1：` 标签。

**证据**：
- 实现：[classroom.js](kb/app/classroom.js#L1012-L1024)
- 断言：[lesson_pack_check.py](medtrain/tests/lesson_pack_check.py#L61) 要求 `E1：` 且 `L1：`
- 结果：9/10，唯一失败项

**影响**：教师拿到的 Markdown 无法与问答页的双引用术语对齐，也不满足“答案可回溯到分区与原文”的产品承诺。

**建议**：按 `E1：CASE-xxx / 右肺上野（bbox）`、`L1：SIGN-xxx / 指南条款` 输出；无来源时明确写“本条无 L1”。

### P1-4 报告—指南双源对照在 7/21 例上是空页

**现象**：`dual_source.json` 中 7 例 `report_available=false`、`coverage=null`、`missing=[]`；5 例无指南要点。

**证据**：

```
cases: 21  mapped: 16  unmapped: 5  avg_coverage: 0.314
report_available=false: CASE-001,002,003,033,034,041,047
无指南要点: CASE-003,033,034,041,047
```

**影响**：双源对照页在这 7 例上只显示标题，没有对照内容；`avg_coverage` 只有 0.314，页面却以“要素核查”为卖点。

**建议**：对这 7 例显示“本病例无可对照报告，改用分区精读”，或补报告文本；页面上给出覆盖率分母，避免“看起来都覆盖了”。

### P1-5 同步推送存在竞态丢写

**现象**：`push()` 在 `busy` 时直接 `return false`，且不会重排定时器。

**证据**：[classroom-sync.js](kb/app/classroom-sync.js#L129-L130)

**触发路径**：一次推送进行中（busy=true）→ 900ms 内又发生写操作 → 定时器触发 `push` → 因 busy 直接返回 → 此后若无新写操作，这次修改永远不会上传。

**影响**：弱网/慢服务下，教师刚改的截止日期或学生刚交的答案可能丢失，且 UI 仍显示“已同步”。

**建议**：busy 时置 `pending=true`，`finally` 里若 pending 再推一次；或改用串行队列。

### P1-6 自适应练习只有 12/21 例能出定位题

**现象**：`drill_bank.json` 38 题中 `localize` 仅 12 题，覆盖 12 例。

**证据**：

```
questions: 38  localize: 12  state: 21  report: 5
localize 覆盖: CASE-005/006/007/015/016/017/036/153/162/202/203/204
```

**影响**：其余 9 例只能出判读题；学生错在这些病例时，“按错题加权出题”会退化成重复同一类题，练习闭环变窄。

**建议**：对全部 21 例生成定位题（正常例出“未见明确异常分区”选项），或明确写“定位题仅覆盖异常例”。

### P2-3 交叉验证脚本依赖 `node` 但无友好提示

**现象**：本机无 `node` 时，`crosscheck.py` 直接抛 `FileNotFoundError`，没有“请安装 Node”或“跳过”的降级。

**证据**：[crosscheck.py](kb/scripts/crosscheck.py#L58)

**影响**：README 把交叉验证列为验收项，新机器上必然失败，且看不出是环境问题还是代码问题。

**建议**：启动前 `shutil.which("node")`，缺失时打印明确提示并以“跳过（非失败）”退出；CI 固定 node 版本。

### P2-4 评测页把 dev + holdout + final 合并成“69/69”

**现象**：`eval.html` 显示“100% 检索准确率 69/69”，但 69 = dev 36（调参集）+ holdout 20（查看过）+ final 13。

**影响**：final 只有 13 条，全对时 95% 置信下界约 0.75；合并展示会掩盖 dev 过拟合，且与报告里“dev 用于调参”的说明冲突。

**建议**：首屏只展示 final（或 holdout+final），dev 折叠为“调参集”；标注样本量与置信区间。

### P2-5 问答库有 19 条跨病例重复问题

**现象**：同一句“右肺上野有什么问题？”在多个病例重复（qid 不同）。

**证据**：`ask_bank.json` 342 条中重复问题 19 条；同病例内重复为 0。

**影响**：绑定当前病例时无碍；但 `resolve_case` 在未指定病例时按分数取首个最大，重复问法会固定落到某一例。

**建议**：可接受则文档说明“问法按病例复制”；否则把分区问法收敛为模板 + 病例参数。

## 六、总体判断

- **主链路可用**：胸片阅片、病例题、对比、课堂考核、学生实验室的端到端验收全部通过，数据自检 441 项全过。
- **新增的 v10.3 同步功能是当前最大风险点**：删除不生效、口令不生效、reset 无鉴权，三项叠加会让“多端课堂”在现场演示时直接暴露。
- **对外数字需要再收一遍**：模型 62%、问答 69/69、每条双引用，这三处都存在“指标口径 > 实际能力”的问题，建议按本报告 P0-3 / P1-2 / P2-4 调整后再对外。
