## 二、修复项（按优先级）

### P0-1 提问页与 DeepWorks 技能会对“治疗类”问题直接作答

**证据**

```bash
python3 .opencode/skills/radhearing-ask/scripts/ask.py "这个气胸需要做胸腔闭式引流吗" --case CASE-006
# → **可以回答** · 置信度 中
# → 库内逐区标注中，本片没有「气胸」的明确描述……

python3 .opencode/skills/radhearing-ask/scripts/ask.py "气胸怎么治疗" --case CASE-006
# → **可以回答** · 置信度 中
```

`read/ask.html` 同样把这两句判为“可以回答”。而“需要吃什么药 / 要不要手术”能正确拒答——说明只是拒答词表漏了“治疗 / 引流 / 置管 / 抽液 / 住院”等词。

**影响**：直接违反站内反复声明的“不提供治疗建议”硬边界。评委只要问一句“气胸怎么治”，产品自己打脸。

**根因**：`kb/scripts/ask_engine.py` 与 `kb/app/ask-core.js` 只靠 28 条拒答问法做匹配，没有独立的“范围分类器”。`student-lab.js` 有 `scopeReason()`（9 类），但提问页没复用它。

**建议**：把 `student-lab.js` 的 `scopeReason` 抽成共用模块（`scope-core.js`），提问页、技能脚本、ask_engine.py 三处统一调用；拒答词表补“治疗/引流/置管/抽液/抗生素/住院/手术/放化疗/靶向”。

**工作量**：0.5 天。

### P0-2 Agent / 五步工作流的证据不接地，双引用在真实链路不成立

**证据（CASE-006 问“右肺中野有什么问题？”）**

```text
依据与出处 · 2 条
- CASE-202 大叶性肺炎（胸片，红箭头）   ← 不是当前病例 CASE-006
- SIGN-002 实变
```

直接调用工作流：

```text
retrieve top: CLM-050-RL, CLM-205-RL, CLM-051-RL …   ← 没有 CLM-006
compose evidence: 0
locate: skipped (no_case_or_bbox)                    ← 给了 case_id 也没用
```

**根因（三处叠加）**

1. `workflow.py` 的 `EVIDENCE_KINDS = ("sign","concept","guideline","case")` **排除了 claim**，而病例逐区原文恰恰在 claims 里；
2. 检索没有“当前病例优先”，CASE-006 与 CASE-202 同源（同一 Wikimedia 图），CASE-202 的文本更“标准”，于是把当前病例挤掉；
3. `locate` 只在有 bbox 时执行，只有 `case_id + zone_id` 时不解析分区，也不把该区原文注入 agent 上下文。

**影响**：这是产品最核心的“E1 影像区域 + L1 原文”承诺。离线降级路径反而能答对（引用 SIGN-001），真实 Agent 路径却引到别的病例——现场演示一旦点“智能问答”，双引用就断。

**建议**

- `EVIDENCE_KINDS` 加入 `claim`；
- `workflow.run()` 接收 `zone_id`，有 `case_id+zone_id` 时把该区的 claim（text/region/bbox/case_id）置顶为证据；
- 检索排序加 `case_id` 权重（当前病例 ×1.5），并在 hint 里明确“E1 必须用当前病例”；
- 验收加一条：CASE-006 RML 的 Agent 回答必须出现 `CASE-006` 或 `CLM-006-*`。

**工作量**：1 天。

### P0-3 提问页召回与意图路由明显弱于课堂影像问答

**证据（`read/ask.html`，15 条应答问题）**

```text
MISS 肺水肿 / 纵隔增宽 / 磨玻璃影 / 空洞 / 钙化 / 支气管扩张 / 肺不张 / 胸膜增厚   （8/15）
ANSWER 气胸在胸片上怎么找   → “本片没有气胸” + 气胸定义引用（结论与引用相反）
ANSWER 气胸和胸腔积液怎么区分 → “本片没有胸腔积液”，没有并列对比
```

同一批问题在 `student-lab.js` 里全部命中：

```text
磨玻璃影 → sign hit
肺水肿   → concept hit
气胸和胸腔积液怎么区分 → compare（胸腔积液 vs 气胸）
```

**根因**：提问页用 `ask_bank.json`（只有“这张片子有没有 X”和分区问法）+ `ask-core.js` 的 dice 匹配；没有“定义/怎么找”意图，也没有 compare 分支。`ask_bank` 里 `磨玻璃影` 等词条根本没有对应问法。

**影响**：首页“提问”是主入口，评委最可能随手问“磨玻璃影是什么”。现在会得到“我没理解这个问题”，而课堂里的同一功能却能答——两个入口自相矛盾。

**建议（二选一，建议 A）**

- A：把提问页切到 `student-lab.js` 的引擎（或抽出 `qa-core.js`），与课堂影像问答共用同一套 sign/concept/compare/scope 逻辑；
- B：给 `ask_bank` 补“X 是什么/怎么找/表现”模板（20 条征象 × 2 问法 = 40 条），并加 compare 分支。

**工作量**：A 约 1 天；B 约 1.5 天。

### P0-5 端口耦合：换端口演示/验收会静默连错服务

**证据**

```text
页面在 8801，点“问 Agent” → POST http://127.0.0.1:8800/api/ask   （agent-lite.js 的 localPage 默认）
页面在 8899 → /api/kb/* 请求 0 条（kb-api.js 把 8899 当静态站）
YZ_PORT=8813 bash scripts/verify_all.sh → 39/41（/api/kb/health 404）
```

**根因**：`agent-lite.js` 把 `localhost` 一律当静态站，默认 `http://127.0.0.1:8800`；`kb-api.js` 用硬编码 `SKIP_PORTS` 判断静态站，8899 在名单里。

**影响**：README/验收文档里出现过 `--port 8899`、`--port 8800`、`8811` 多种端口；换一个端口，页面要么连错实例，要么静默退回静态 JSON，验收出现假失败。

**建议**：统一改成“先探测同源 `/api/health`（600ms 超时），失败再退回 8800/静态”；删除硬编码端口白名单，只保留 `file:` 与 `github.io` 的静态判断。

**工作量**：0.5 天。
