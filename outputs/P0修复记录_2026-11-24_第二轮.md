## 二、P0-2 Agent 证据不接地

**根因**

1. `workflow.py` 的 `EVIDENCE_KINDS` 排除了 `claim`，病例逐区原文进不了证据；
2. 检索没有“当前病例优先”，CASE-006 与 CASE-202 同源，CASE-202 被排到前面；
3. `locate` 只在有 bbox 时执行，`case_id + zone_id` 不解析分区。

**改动**

- [yingzhi/serve/workflow.py](../yingzhi/serve/workflow.py)：
  - `EVIDENCE_KINDS` 加入 `claim`；
  - 新增 `CaseEvidence`：按 `case_id + zone_id` 直接读 `chest_reading.json` / `claims.jsonl`，把当前病例的逐区原文置顶（有 claim 用 claim id，没有用病例 id）；
  - 有当前病例时，其他病例的 `claim` / `case` 不进入证据区；
  - 当前分区挂载的征象词条（如 `SIGN-002`）补进证据，保证 L1 有定义原文；
  - `locate` 支持 `case_id + zone_id`（无需 bbox），返回 `source=case_zone`；
  - `run()` 新增 `zone_id` 参数。
- [yingzhi/serve/main.py](../yingzhi/serve/main.py)：把 `zone_id` 传给工作流；工作流证据非空时，agent hint 直接使用本地证据，不再让它从零 grep。

**前后对比（CASE-006 右肺中野）**

```text
修复前：
  依据与出处：CASE-202 大叶性肺炎（胸片，红箭头） / SIGN-002 实变
  grounding=general, cited=[CASE-202, SIGN-002, ...]

修复后：
  依据与出处：CASE-006 大叶性肺炎（箭头标注） / SIGN-002 实变
  grounding=grounded, cited=[CASE-006, SIGN-002], marker_ok=true
  正文开头：这张片子的右肺中野有大片实变，是明确的异常。
```

**回归**

- `python3 yingzhi/serve/test_workflow.py`：11/11（新增当前病例置顶、claim 命中、无 bbox 定位 3 项）
- 真实 Agent（`--port 8802`）实测：CASE-006 RML / RLL / LUL 均只引用 CASE-006（或 CLM-006-*）+ 对应征象。

## 三、P0-5 端口耦合

**根因**

- `agent-lite.js` 把所有 localhost 当静态站，默认 `http://127.0.0.1:8800`；
- `kb-api.js` 用硬编码 `SKIP_PORTS` 判断静态站，8899 被误判为静态。

**改动**

- [yingzhi/serve/main.py](../yingzhi/serve/main.py)：动态服务给 HTML 注入 `<meta name="rc-api" content="same-origin">`。
- [kb/app/agent-lite.js](../kb/app/agent-lite.js)：有 meta 就同源优先；本地静态页才退回 8800；GitHub Pages 明确提示未配置。
- [kb/app/kb-api.js](../kb/app/kb-api.js)：删掉硬编码端口表，只有 meta 或显式 `?api=` 才探测；静态站不再产生 404。
- [kb/app/clinic.js](../kb/app/clinic.js)：静态站上传不再发 POST，直接显示“未连接动态服务”。

**验证**

```text
页面在 8801（动态）→ POST http://127.0.0.1:8801/api/ask      （修复前是 8800）
页面在 8801（动态）→ /api/kb/health 同源命中
页面在 8811（静态）→ 0 条 /api 请求，无 404
YZ_PORT=8813 bash scripts/verify_all.sh → 41/41（修复前 39/41）
```
